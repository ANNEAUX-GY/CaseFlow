# CaseFlow 案件指派系统 · 部署教程

> 这份教程是给**装系统的人**看的，不是给用系统的人看的。
> 全程不用装 Java、不用装数据库（试用模式），解压、双击、打开浏览器，三步就完事。
> **照着做就行，看不懂的名词不用管。**

## 一、第 1 步：解压

拿到的是一个压缩包，文件名类似：

```
caseflow-portable-1.0.0-20261014-210000.zip
```

**把它解压到 D 盘**，建议就放这个位置：

```
D:\CaseFlow
```

> **两个注意**：
> - 路径**别带中文、别带空格**，不然容易出莫名其妙的错。
> - 一定要**完整解压**，不要图省事直接在压缩包里双击运行——那样会缺文件。

解压完，文件夹里应该有这些东西：

| 看到什么 | 是什么 |
| --- | --- |
| `★ 先看我.txt` | 最简版说明，30 秒看完 |
| `启动.bat` | **双击这个启动** |
| `停止.bat` | 停止服务（一般用不上，关窗口就行） |
| `放行防火墙.bat` | 想让同事也能访问就双击它 |
| `数据库配置.bat` | 只有正式模式才用得到 |
| `case-flow-backend.jar` | 程序本体，**别动它** |
| `runtime\` | **自带的 Java**，所以您不用另外装 Java |
| `部署说明\` | **部署教程和建库脚本都在这里面**，遇到问题先翻它 |
| `data\` | 数据都存在这里 |
| `logs\` | 出问题看这里 |

## 二、第 2 步：启动

**双击【启动.bat】**。

会弹出一个黑色的窗口，问您用哪种模式：

```
请选择运行模式：

   1 = 试用模式（不用装数据库，先看看效果）
   2 = 正式模式（连接单位自己的 MySQL 数据库）

请输入 1 或 2 然后回车（直接回车 = 1）：
```

**第一次就先敲 `1`，回车。**

> **1 和 2 到底选哪个？**
>
> - 选 **1（试用模式）**：不用装任何数据库，数据就存在本机文件夹里。适合先看看效果、或者单机自己用。
> - 选 **2（正式模式）**：连单位自己的 MySQL 数据库。多人正式使用选这个，但要先把数据库准备好（见第五章）。

敲完回车，窗口会开始刷一堆字，**等 20 到 40 秒**。

看到类似这样的提示，就成功了：

```
启动完成后，浏览器打开：
   http://localhost:8080/api/
```

> **★ 这个黑色窗口千万不要关！关掉就等于把服务停了。★**
> 窗口最小化就行，让它一直在后台待着。

## 四、想让同事也能打开怎么办

刚才的 `localhost` 只有本机能打开。要让**局域网里别的电脑**也能用，做两件事：

### 第 1 件：放行防火墙（只做一次）

**双击【放行防火墙.bat】**，会弹出权限提示，点【是】。

看到「已放行端口 8080」就成了。

### 第 2 件：把地址换成内网 IP

先查这台机器的内网 IP：

1. 开始菜单搜 `cmd`，打开命令提示符。
2. 敲 `ipconfig`，回车。
3. 找到 **IPv4 地址**，长得像 `192.168.1.100`。

然后让同事在浏览器里输入：

```
http://192.168.1.100:8080/api/
```

（把 `192.168.1.100` 换成刚才查到的那个 IP）

> **★ 一定要找另一台电脑实际试一次。★**
> 在**自己这台机器**上能打开，**不代表**别人那台能打开。
>
> **打不开怎么查**（按顺序）：
> 1. 防火墙放行了没？（重新双击一次【放行防火墙.bat】）
> 2. IP 抄对了没？（IP 会变，重查一次）
> 3. 两台电脑在不在同一个局域网里？
> 4. 启动窗口还开着没？（关了就等于停了服务）

## 五、正式模式：连接单位的 MySQL 数据库

> 多人正式使用，用这个。只用试用模式的话，这章可以跳过。

### 第 1 步：把数据库建好

打开 **`部署说明\建库语句\00-建库怎么用（先看我）.txt`**，里面有三个脚本，**按顺序执行，一个都别跳**：

1. **`1-建库和账号.sql`**——建一个叫 `case_flow` 的库，再建一个叫 `caseflow` 的账号并授权
2. **`2-建表.sql`**——建 19 张表
3. **`3-建索引.sql`**——建索引（**正式库必做，不做数据一多就慢**）

> **两件必须注意的事**：① 执行 `1-建库和账号.sql` 之前，先打开它把里面的口令改成你自己的、**并记住它**，等下要填进【数据库配置.bat】；② 表程序启动时会自动建，但 **`3-建索引.sql` 一定要单独执行一遍**。

> 这三个脚本在包里的 `部署说明\建库语句\` 下；另外那个小体积的**部署资料包**里也有同样一份，方便单独发给负责建库的同事。

### 第 2 步：填数据库口令

用**记事本**打开 **`数据库配置.bat`**，长这样：

```
set "MYSQL_HOST=127.0.0.1"
set "MYSQL_PORT=3306"
set "MYSQL_DB=case_flow"
set "MYSQL_USER=caseflow"
set "MYSQL_PASSWORD=请改成你自己的数据库口令"
```

**把最后一行那个中文，换成您建账号时设的口令。**

如果数据库不在这台机器上，`MYSQL_HOST` 也改一下（填数据库服务器的 IP）。

改完**保存**。

> 这是整个部署里**唯一必须改**的地方。

### 第 3 步：重新启动

关掉黑色窗口，重新**双击【启动.bat】**，这次敲 `2`。

等它起来，还是打开 `http://localhost:8080/api/`。

> **如果起不来**，多半是数据库连不上。检查三样：
> ① MySQL 服务开着没；② `数据库配置.bat` 的口令改对没；③ 地址和端口对没。
> 具体报错可以翻 `logs\` 文件夹里最新的日志。

## 六、日常怎么用

### 开机

双击【启动.bat】→ 选模式 → 等 30 秒。

> 如果希望开机自动启动，可以把 `启动.bat` 的快捷方式放进这个文件夹：
> 按 `Win + R`，输入 `shell:startup`，回车，把快捷方式拖进去。

### 关机 / 停止

**直接关掉那个黑色窗口就行。**

如果窗口找不到了（比如被误关过），双击【停止.bat】。

> **养成习惯**：先关窗口，再关机。**别直接拔电源、别强行结束进程**，容易伤数据。

### 备份（这条最重要）

| 数据在哪 | 怎么备份 |
| --- | --- |
| **附件**（`data\uploads` 文件夹） | 整个文件夹复制走 |
| **业务数据**（正式模式的 MySQL） | 用 `mysqldump` 导出 `case_flow` 库 |

导出命令：

```
mysqldump -uroot -p case_flow > case_flow_备份日期.sql
```

> **★ 建议每天备一次，两样一起备，存到别的机器上。★**
> 只备份在同一块硬盘里，硬盘坏了就全没了。

### 上传限制

| 项目 | 上限 |
| --- | --- |
| 单个文件 | 50 MB |
| 一次请求 | 100 MB |

超了传不上去，得先把文件拆小。

### 登录时效

登录后 **12 小时**内有效，到点了重新登录即可。

## 七、以后升级到新版本

系统更新时，发布方会给一个**升级补丁包**（很小，只有几十 MB），里面就三样东西：

```
升级说明.txt          ← 照它做就行
case-flow-backend.jar ← 新的程序本体
建库语句\             ← 一般用不上，遇到提示再跑
```

### 升级四步

**第 1 步：停服**

双击【停止.bat】，等窗口显示已停止。

**第 2 步：备份（铁律，不能省）**

两样东西备份一下（详见第六章「备份」）：

- 数据库（正式模式：`mysqldump` 导出 `case_flow` 库；也可以直接在服务器上做个快照）
- `data\uploads\` 附件文件夹复制一份

**第 3 步：覆盖一个文件**

把新的 `case-flow-backend.jar` **拖进安装目录，替换掉旧的**。

> **先把旧的改个名留着**（比如改成 `case-flow-backend.jar.old`），万一新版有问题，换回来重启就恢复了。

**第 4 步：启动并验证**

双击【启动.bat】，等 30 秒，浏览器打开地址，**能正常登录、能打开案件列表**就说明升级成功。

### 千万不能覆盖的三样东西

| 不能动 | 为什么 |
| --- | --- |
| `数据库配置.bat` | 里面有您的数据库口令，覆盖了就得重填 |
| `data\` 文件夹 | **所有业务数据和附件都在这里** |
| `runtime\` 文件夹 | 自带的 Java 运行环境，每次升级都不用换 |

> 只覆盖 `case-flow-backend.jar` 这一个文件，其它一律不动，就绝对不会出问题。

### 数据库要不要手工改？

**一般不用。** 程序每次启动时会**自己检查并升级表结构**：

- 有新表 → 自动建好
- 老表要加新字段 → 自动补上

所以只要换 jar、重启，数据库就跟着升级了。**您不用手工执行任何建表语句。**

> **唯一例外**：如果这次更新带来了**新的查询索引**，升级说明里会特别写出来，那时才需要手工跑一次 `建库语句\3-建索引.sql`。
> 如果执行时提示 `Duplicate key name`，说明这个索引早就建过了，**直接忽略即可**，不是错误。

### 已经录进去的数据会不会被改动？

**不会。** 程序对数据库只做两件事：

| 做什么 | 怎么做的 |
| --- | --- |
| 建缺失的表 | 已有的表**一律不碰** |
| 补新增的字段 | **只加不删**，不改字段类型，不改表名 |

案件、待办、领导意见、嫌疑人、附件、账号、组织机构、案件类别——**全部原样保留**，程序不会删除、不会清空、也不会覆盖您已经填好的内容。

另外有一批「旧数据格式整理」（比如把旧字段的内容搬到新字段）。这类动作**每个数据库只跑一次**，跑完会记在数据库的 `schema_migration_mark` 表里，以后启动直接跳过。所以第二次、第三次升级都不会再动这些数据。

> 唯一会看到变化的地方：如果库里还留着已下线的「民事」分类案件，日志里会出现一条提示，**但案件本身不会被改动**，需要的话由管理员在界面上手工调整。

### 出问题了怎么回退

把第 3 步留着的旧 `case-flow-backend.jar.old` 改回 `case-flow-backend.jar`，重启即可。

> 注意：**表结构升级之后不会自动回退**（新表、新字段会留在数据库里）。旧版程序一般不受影响，但仍建议回退后一并恢复第 2 步的数据库备份。

> **★ 升级前先备份。★** 这是铁律。

## 九、常见问题

**Q1：双击【启动.bat】，黑窗口一闪就没了？**

说明启动失败了。先看 `logs\` 文件夹里最新的日志。常见原因是端口被占（见 Q2），或者正式模式数据库连不上（见 Q3）。

**Q2：提示端口 8080 被占用？**

说明已经有一个在跑了，或者别的程序占了这个端口。先双击【停止.bat】把旧的停掉；如果还报，就是别的软件占了 8080，得找技术人员换端口。

**Q3：正式模式起不来，说数据库连不上？**

按顺序查三样：① MySQL 服务开着没；② `数据库配置.bat` 里的口令改对没；③ 数据库的 IP 和端口填对没。

**Q4：我自己能打开，同事打不开？**

① 双击一次【放行防火墙.bat】；② 地址里的 `localhost` 换成本机内网 IP；③ 找另一台电脑实际试一次。

**Q5：登录进去什么都没有？**

数据是空的，正常。先建案件，或者在试用模式下看看演示数据。

**Q6：boss 的密码在哪改？**

登录后进【用户管理】，找到 boss 那条，点重置密码。**正式上线第一件事就做这个。**

**Q7：能装在没联网的电脑上吗？**

能。这个包**自带了 Java 运行环境**，不需要联网、不需要装任何东西，拷贝过去就能用。只有正式模式连 MySQL 时需要能连到数据库服务器。

**Q8：换一台电脑，怎么把数据搬过去？**

把老的 `data\` 文件夹整个复制到新电脑同一个位置，然后在新电脑上启动即可（试用模式）。如果用的是正式模式，数据在 MySQL 里，需要在新电脑的 `数据库配置.bat` 里指向同一个数据库。

## 十、还搞不定怎么办

按这个顺序做：

1. 看一眼 `logs\` 里最新的那个日志文件，报错信息都在里面。
2. 看一下黑色窗口里最后几行写了什么。
3. 对着第八章「常见问题」一条条排查。
4. 还不行，**把这个文件夹整个打个包发给我们**，并说明：您做了什么操作、看到了什么报错。

> **求助时请一起提供这三样**：日志文件、报错截图、您操作的步骤。
> 有这三样，问题基本一次就能定位。
