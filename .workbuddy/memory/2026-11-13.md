## 关联案件下拉增强（commit f526680）

### 需求
工作记录本「关联案件」下拉检索增强：
- 管理用户→列出所有案件；民警→只列本人经办；均按截止时间近→远排序。
- 忘记案件名时，可打「刑事/行政/某小类」关键词弹出该类案件。
- 支持按嫌疑人姓名模糊搜匹配案件。

### 实现
- 前端 WorkLog.vue searchCases 改造：
  - 同一关键词并行发 keyword + suspectName 两路 caseApi.page，合并去重。
    （后端 keyword 与 suspectName 是 AND 关系，必须分两路搜再合并，不能同时传。）
  - 空关键词时 @visible-change 触发 loadCases 加载全量/本人列表。
  - 排序 sortField=deadline sortOrder=asc；前端 sortCaseOptions 再兜底
    「空 deadline 排最后」（MySQL 里 NULL 默认排最前，前端要纠正）。
  - 民警加 onlyMine=true（后端 scopeToSelf 对非管理层强制只看本人）。
  - caseLabel 带「类型·案件名（编号）｜截止日期」。
- 后端 CaseService.buildWrapper keyword 分支新增 caseTypeCodeOf：
  「刑事→CRIMINAL / 行政→ADMINISTRATIVE / 未立案/初查→PRELIMINARY」，
  命中时加 eq(caseType, code) 精确匹配。根因：caseType 存英文码，原来搜中文名落空。

### 教训
- caseType 存英文码（CRIMINAL 等），中文名在 DictHolder.CASE_TYPE 字典里，
  后端 keyword LIKE 只匹配 name/caseNo/category/filingNo/description，不含 caseType，
  搜「刑事/行政」会 total=0。要让大类中文名可搜，需额外做中文名→码映射。
- keyword 与 suspectName 在 buildWrapper 是独立 if 拼 AND，别同时传；前端并行两路合并。
- deadline 排序：DB 里 NULL 排最前，但「无截止时间」应排最后，前端要二次纠正。
- 项目里「初查」= PRELIMINARY = 「未立案」（DictHolder 里 PRELIMINARY 的中文名就是「未立案」）。

## 阶段变更模式开关 + 自动变更异议撤回（commit 4305b0e）

### 需求
变更案件状态加「自动/手动/两套都要」切换机制，支持自动变更后的民警异议退回、领导撤回。
用户确认：全局开关（非按案件）；自动范围=刑拘+取保都自动；异议链路这次一起做。
提示位置：待办总览+工作台（复用已有「状态变更待审批」面板）。

### 关键设计
- 新增 system_config 键值表存 flow_change_mode（AUTO/MANUAL/BOTH），默认 MANUAL。
  新表走 schema.sql CREATE TABLE IF NOT EXISTS，无需登记 NEW_COLUMNS。
- ApprovalService.applyMeasure 接入开关：
  - 拘留/逮捕 → 目标 STAGE_DETAIN；取保/监视居住 → 目标 STAGE_BAIL（补了取保自动转，原来只有刑拘转）。
  - AUTO/BOTH → setFlowStage + recordAutoFlow（result=AUTO 的 FLOW 留痕）。
  - MANUAL → recordManualPending（result=PENDING 的 FLOW 申请，落入 Dashboard 待审批面板）。
  - 关键：原 applyMeasure 里 custodyExecuted 已自动 setFlowStage(DETAIN)，改成按开关分派；
    手动模式下措施照常落地（事实已发生），但阶段不变、等管理确认。
- FlowService 新增：
  - disputeAutoFlow：承办人对 AUTO 提异议 → DISPUTE。
  - reviewDispute：领导同意退回（flow_stage 回 from_stage）/ 不同意（REJECTED）。
  - withdrawAutoFlow：领导直接撤回 → 回 from_stage。
  - latestAutoFlowOf：查本案可异议/可撤回的 AUTO/DISPUTE 留痕。
  - pendingDisputes：全局限待审批异议（工作台用）。
- 只回退 flow_stage，不回退 case_measure（已执行措施是事实，保留）。

### 教训/口径
- 阶段（flow_stage）与措施（case_measure）是两套东西：撤回/退回阶段变更不能抹掉已登记的措施。
- case_approval.result 新增取值 AUTO（自动变更留痕）/ DISPUTE（异议中）/ REJECTED（驳回异议）/
  WITHDRAWN（已撤回），与原有 PENDING/APPROVED/RETURNED/STALE 并存。
- 开关入口放账号管理页（管理层专属），待确认变更的提示天然复用 Dashboard 已有
  「状态变更待审批」面板（因为 MANUAL 模式生成的也是 PENDING FLOW 申请）。
- Edit 工具删除大段注释时容易误删方法签名/注解，本次 returnBack 就被删坏过一次，需小心。

## 结案自动/手动机制（本 commit，参照 4305b0e）

### 需求
结案也分「自动/手动」两套，操作与方法与「变更案件状态」相同：
- 刑事：撤案/移送预审/移送其他单位 = 结案；行政：处罚/不予处罚/终止调查 = 结案。
- 自动结案后盯办提醒管理用户+办案民警，民警可异议退回、领导可撤回或审批异议。
- 已有「一键结案」（directClose 立即生效 + submit/review 申请审批）不动。
用户确认：①触发时机=「登记结案结果」动作；②独立结案开关（非复用 flow 开关）。

### 关键设计
- SystemConfigService 新增 CLOSE_MODE key + closeMode()/autoCloseEnabled()/manualCloseEnabled()/setCloseMode()，
  与 flow_change_mode 完全同构（AUTO/MANUAL/BOTH，默认 MANUAL）。
- 新增「登记结案结果」动作 registerOutcome（CaseCloseRequestService）：
  - AUTO/BOTH → applyOutcome 落地（撤案→CANCELLED，其余→DONE）+ 记 case_approval(CLOSE,AUTO)。
  - MANUAL → 记 case_approval(CLOSE,PENDING)，领导 reviewManualClose 审批后落地。
- 复用 case_approval 表（approveType=CLOSE）承载结案留痕，**零库改动**：
  flow_action 存 outcome 编码、from_stage 存结案前 status（回退据此回 open）。
- 异议/撤回/审批完全镜像自动变更：
  disputeAutoClose / reviewCloseDispute / withdrawAutoClose / latestCloseTraceOf /
  pendingCloseApprovals / pendingCloseDisputes。
- 回退=reopenCase：changeStatus 回退到结案前 status（IN_PROGRESS 兜底）；结案结果本身是客观事实不抹。
- DashboardVO 新增 closePending/closeDispute 计数；Dashboard 新增「待确认结案」「结案异议待审批」两按钮+弹窗。
- CaseDetailDrawer 结案区新增「登记结案结果」按钮 + closeAuto 留痕展示（PENDING/AUTO/DISPUTE 三态）。

### 口径/教训
- case_close_request（一键结案）与 case_approval(CLOSE)（登记结案）是两条独立链路，
  别混写：登记结案统一只走 case_approval，case_close_request 只留给一键结案，否则双写 PENDING 会串到旧审批流。
- 结案回退不能只回 flow_stage（结案改的是 status），要回 status；from_status 存结案前 status。
- 复用字段（flow_action 存 outcome、from_stage 存 status）比加列省去 schema+升级包全套流程，
  但要在类头注释写清楚字段语义，否则后来人误读。
