## 三级浏览改造：大类卡片 → 小类卡片 → 栏目页，退出逐级退回

用户要求：三个大类（刑事/行政/其他）保持不变；进大类后先看该大类的小类卡片
（刑事 → 电诈/接触性诈骗/故意伤害类/盗窃类/其他/殴打）；点小类才进案件；
**退出要层层退回（先退小类再退大类）**。两个岔路用户都选了推荐项：
所有入口都过小类 + 顶栏按钮逐级变。

### 改法（前端 8 个文件，无后端改动）
- `store/caseType.js`：新增 `LEVEL3_PATHS`（/watch /todos /cases /reminders）、
  `CATEGORY_AWARE_PATHS`（/cases /watch）、`BOARDS_PATH`、`PICKER_PATH`，
  以及纯函数 `parseLevel3()`（to 参数白名单校验）、`boardsUrl()`（拼第 2 级地址）、
  `levelOf()`（路径 → 层级 1/2/3）。
- `CaseTypePicker.vue`：选完大类**一律**进 `/case-boards`，并把最终落点
  （含原有 status/employeeId 等筛选）用 `to` 带过去。
  **删掉了原来的例外分支**（以前带 query 的跨栏目跳转直达列表、不截胡）。
- `CaseBoards.vue`：读 `to` 决定落点；落点栏目没有小类维度时只给一张「全部」卡；
  卡片点击带上 `category` 落到目标栏目。
- `Layout.vue`：顶栏按钮按 `levelOf(route.path)` 变形 ——
  第 3 级「返回类别」→ 第 2 级「返回大类」→ 第 1 级「退出类型」；
  类型条同时显示大类/小类两个标签。
- `CaseList.vue` / `WatchView.vue`：入口带 to；提示文案改为"逐级返回"。
- `styles/index.css`：新增 `.cf-ctypebar__sep`。
- `router/index.js`：/case-boards 的 title 从「按类别浏览」改「选择小类」。

### 顺手修掉的两个真 bug（都是 e2e 暴露的）
1. **「未分类」卡片进来当场失效**：`cascadeFilter` 的 watch 会把 `query.category`
   一起清空，而 NONE 不在级联树里、级联必为空 → 筛选被清掉。
   CaseList 与 WatchView 两处 watcher 都加了「空级联 + NONE 时不清 category」的保护。
2. **WatchView 根本不读地址栏**：它只认页内级联控件，小类卡片带 `?category=` 跳过来
   会"跳到了却没筛"。补了 `syncCategoryFromRoute()` + `watch(route.query.category)`。
3. 另有一处显示问题：待办总览那张「全部」卡曾显示"共 N 件"（其实是**案件数**，
   但点进去是待办列表，含义对不上）→ 加 `noCount` 不显示数字。

## 列表「嫌疑人」列：显示姓名，多人显示「张三等N人」

用户要求：有嫌疑人的案件展示嫌疑人姓名；多个则展示「张三等X人」。

### 原因
列表接口只在**详情模式**填充 `suspects` 姓名列表，列表模式只给了 `suspectCount`（数字），
所以盯办/案件管理列表的「嫌疑人」列一直只显示人数、且无嫌疑人时是「—」。

### 改法
- 后端 `CaseService`：`suspectCounts()`（只算数量）→ `suspectsOf()`（返回
  `Map<Long, List<CaseSuspect>>`，一次 IN 查询 + **按 id 升序**保证"首位"稳定，
  列表刷新不会换人）。`toVO` 列表模式同时填 `suspectCount` 与精简 `suspects`
  （只含 id/姓名/性别 —— **列表用不到身份证号/手机号，不送到前端**，最小暴露）。
  `full=true`（详情）仍走 `suspectService.listOf` 覆盖为完整字段。
- 前端 `utils/format.js` 新增两个纯函数（**唯一口径**，别再各处自己拼）：
  - `suspectLabel(row)`：1 人=姓名，多人=`首位等N人`（N=**总人数**，含首位本人，
    这样与列上的人数永远对得上），0 人=''
  - `suspectNamesText(row)`：完整名单（「、」分隔），仅多人返回，挂 tooltip 用
- `WatchView.vue` 与 `components/CaseTable.vue`（被案件管理/工作台/我的案件/到期提醒共用）
  两处模板都改：列宽 70→140，用 `suspectLabel` + `el-tooltip` 显示全名单。
- `styles/index.css`：新增 `.cf-suspect`（加粗 + 省略号保护）。

### 验证
- 新增 `scripts/cf-e2e-suspects.mjs`：**13 项断言，零控制台错误**。
  覆盖案件管理与案件盯办**两套模板**（容易只改一处）+ tooltip 全名单 + 列宽不截断。
- 脚本**自管测试数据**：自己给案件补临时嫌疑人造"多人"场景、跑完删掉，
  断言比对的是**接口实时算出的期望值**而非写死的「张三等3人」——
  所以任何数据状态下都能重跑，也不会往真实库留假数据。

### 踩坑（下次直接照做）
- **Element Plus 的 tooltip 浮层没有 `role="tooltip"`**，是 `.el-popper.is-dark.el-tooltip`。
  用 `[role="tooltip"]` 选会一个都选不到（页面另有一堆隐藏的 select 下拉 popper，需按可见性过滤）。
- **测 hover 时坐标要取在文字 span 上，不能取 td 中心**：列宽 140 而文字只有 ~60px
  且左对齐，td 中心已落到文字右外侧，hover 不触发。另外鼠标要从远处分步移入，
  一步到位时平台可能不派发 mouseenter。
- **页面加载会先渲染一帧旧数据**（类型筛选生效前），立刻读表格会拿到上一次的行、
  断言假失败 → 用「等表格内容稳定」再读。
- 盯办默认落在**初查**子页签（无强制措施 + 在办），对照案件必须在这个范围内，
  否则行根本不出现（刑拘案件在另一页签）。
