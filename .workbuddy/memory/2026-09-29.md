## 组织树「树状图」标签叠字返工（重要坑）

- 现象：同级叶子节点（如「陈组员 组员·侦查一组」「刘组员 组员·侦查一组」）汉字横向叠在一起。
- 真因：原 label 是**单行**富文本（姓名+职务·部门+在手数拼一行），宽度 ~150px，而 ECharts tree 的布局**只按 symbolSize 算间距，不考虑 label 尺寸**，同级间距装不下就压字。
- 修法（`EmployeeTree.vue`）：label 改**定宽三行堆叠**——`{n0|姓名}` / `{meta|职务 · 部门}` / `{load|在手 N}`，每个 rich 段都设 `width: LABEL_W(104) + align: center + overflow: 'break'`，长文本在框内折行，横向不再越界。
- **ECharts 富文本要点**：rich 段的 `lineHeight` **不**决定背景色块高度，色块高 = `fontSize + paddingTop + paddingBottom`。想让白字压在色块上有呼吸位，必须靠 `padding: [3, 4]`（12.5 字号 → 18.5px 色块）。`verticalAlign: 'middle'` 对 rich 段无效。
- 其他加固：`edgeForkPosition: '38%'` 把折线分叉点抬到子节点标签**上方**，避免横线穿过三行文字；`treeHeight` 按层级数动态（`clamp(430, 118*depth+90, 760)`），层级深时画布自动变高。
- 层级配色改为四级蓝（`#12294a` → `#1b4a8c` → `#2a5da6` → `#4a76bd`），弃用金色块（金色底 + 白字对比度不足）。
- 验证手段（可复用）：本机 Chrome 无头截图即可核对 ECharts 版式——`chrome.exe --headless=new --no-sandbox --force-device-scale-factor=2 --window-size=1120,720 --virtual-time-budget=2500 --screenshot=<输出>`，输出目录必须在 `%TEMP%`（写 D:\ 会被拒），再用 `.venv` 里的 Pillow 裁切/放大局部核对像素。**注意 file:// 会被缓存，改完要加 `?v=N` 或换 `--user-data-dir`。**

### 三个必须记住的坑（都实测踩过）

1. **mysqld 在非 ASCII 路径下必挂**。项目路径 `D:\案件指派demo` 含中文时，mysqld 把 argv[0] 和选项里的路径在第一个非 ASCII 字符处**截断**——日志表现为 `D:\ (mysqld 8.0.28) starting as process ...`、`Failed to set datadir to 'D:\data\'` 后退出。**诡异点**：`--initialize` 能正常跑完、`--verbose --help` 也能解析出正确路径，唯独正常启动失败；改选项文件编码（UTF-8/GBK）、改命令行传参全都无效。**唯一可靠解法：实例放纯 ASCII 路径。**
2. **JDBC URL 的 `characterEncoding` 必须写 Java 字符集名 `UTF-8`**，写 MySQL 的 `utf8mb4` 会抛 `Unsupported character encoding 'utf8mb4'`（Connector/J 8 直接拒绝）。这是潜伏已久的 Bug——之前一直用 H2，从没暴露过。同时补了 `connectionCollation=utf8mb4_general_ci`。
3. **my.ini 不要开 `skip-name-resolve`**。开了之后 127.0.0.1 不再被解析成 localhost，`root@localhost` 匹配不上，报 `Host '127.0.0.1' is not allowed to connect to this MySQL server`。另外 Windows 版 mysqld 按**系统 ANSI(GBK)** 解码选项文件，UTF-8 写的中文路径会变乱码。

## 最近操作可点开看详情 + 撤回（Ctrl+Z）

- 用户诉求：「最近操作处要求能够点击打开查看具体执行了什么任务（比如指派、更改期限），并且能够支持撤回操作（即 ctrl+z 的作用）」。
- 做法：**写操作前后各存一份对象完整快照**，撤回 = 把 `snapshot_before` 原样写回。
  - `operation_log` 新增 5 列：`snapshot_before` / `snapshot_after`（TEXT，MySQL 上 TEXT 不能带 DEFAULT，只写 NULL）/ `undone` / `undo_log_id` / `undo_of`。
  - 快照 JSON 结构（`support/CaseSnapshot`）：`{exists, info, assignees, files}`。`exists:false` 统一表达「当时不存在」——新建的 before、删除的 after 都是它，于是「撤回」可以统一成一句「把 before 写回去」。
  - `CaseSnapshotService`：`capture` / `restore` / `diff`。restore 用全字段显式 `LambdaUpdateWrapper.set(...)`（updateById 会跳过 null，清空期限这类撤回会失效）；指派关系**先清空再按快照带原主键逐一写回**（连 REPLACED 历史一起还原）；附件只对齐 `case_id`，不删记录。
  - **带显式主键插入必须手写 SQL**：MyBatis-Plus 的 `IdType.AUTO` 在 insert 时会省掉主键列，所以 `CaseInfoMapper/CaseAssigneeMapper` 各加了一个 `@Insert insertWithId`。撤回删除案件时要还原成**原来的 id**，否则历史日志的 target_id 会指向不存在的案件。
- 撤回规则（宁可少撤不可撤错）：只有案件类写操作可撤；已撤过不能再撤；**必须是该案件上最新的一条**（否则会覆盖之后的改动）；撤回本身也记一条 `action=UNDO` 的日志，所以还能再撤回一次 = 重做。
- 接口：`GET /logs`、`GET /logs/recent`、`GET /logs/{id}`（含 `changes` 变更明细 + `undoHint` 不可撤回原因）、`POST /logs/{id}/undo`、`POST /logs/undo-latest`。
- 前端：工作台「最近操作」每条改成 `<button>`（可 Tab 聚焦），点开 `OperationLogDrawer`（执行内容 / 操作人 / 涉及案件可点进详情 / 变更前-变更后表格 / 撤回按钮）；面板头加「撤回上一步」；工作台监听 Ctrl+Z（输入框内不拦截，交还给文本撤销）。
- 验证：`scripts/verify_undo.py`（新增）走 HTTP + 直连 SQL 双路核对，全绿——撤回新建→案件消失；撤回删除→**同 id 还原且字段与改派历史逐行一致**；撤回指派+改期限→期限与承办人精确回退；撤回后再撤回=重做；较早那条被拒并给出原因；登录日志不可撤回。
- 前端真实页面核对：`cf-logshot.mjs`（在 `C:\Users\adamin\.workbuddy\binaries\node\workspace`）——先用接口改一个案件优先级产生 UPDATE 日志，再从页面点开、撤回、确认，最后**数据回到原样**，零脏数据。实测 `priority NORMAL -> URGENT -> NORMAL`。

### 这次踩到的两个前端/后端坑

1. **`@Resource` 先按字段名找 Bean**。`LogController` 里写 `private OperationLogService logService;` 会撞上 `support` 包的 `LogService`，启动报 `BeanNotOfRequiredTypeException: Bean named 'logService' is expected to be of type ...`。字段改名 `operationLogService` 即可。
2. **`.cf-oplog` 这种「靠兄弟列 flex 撑高」的写法会循环依赖**。一开始给 body 只写了 `flex:1; min-height:230px`，结果列表把整页顶到 1139px（20 条 × 52px）。**必须给确定高度**（`height:230px; overflow:hidden`），同排两栏才会都落在 276px（44 表头 + 230 主体 + 2 边框）。

### 已有库升级字段的做法

`schema.sql` 全是 `CREATE TABLE IF NOT EXISTS`，对已存在的表**不会补列**；MySQL 的 `ALTER TABLE ADD COLUMN` 又不支持 `IF NOT EXISTS`（H2 支持、MySQL 不支持），没法写进同一份脚本。所以新增 `bootstrap/SchemaMigration`（`ApplicationRunner`，`@Order(HIGHEST_PRECEDENCE)`）：启动时用 `DatabaseMetaData.getColumns` 一次拉全库的 `表.列` 集合，缺哪列补哪列，H2/MySQL 通用、可重复执行。**已确认执行时机安全**：`spring.sql.init` 由 `AbstractScriptDatabaseInitializer`（`InitializingBean`）驱动，在所有 `ApplicationRunner` 之前跑完。以后加列同步登记到它的 `NEW_COLUMNS`。
