# 2026-10-30

## 一键结案 + 变更案件状态（申请+审批双通道，commit 395be4e）

### 需求
经办人申请「变更案件状态」「结案」，案管或领导审批通过或直接操作。

### 关键设计
- **新增「案管 CASE_MANAGER」角色**：权限与法制员同级（isFullAccess），是审批人。
  审批人 = 除 STAFF/JUDGE 外的所有角色（所长/副所长/队长/法制员/案管/管理员）。
- **变更案件状态 = 升级现有 FlowService.transfer**（用户明确"就是升级现有阶段流转"）：
  - CaseFlowTemplate.transitionsOf 初查阶段补上出口：INITIAL→DETAIN / INITIAL→BAIL
    （原来初查无出口，靠 measure 登记自动转段）。
  - transfer 内部分派：isFullAccess→直接流转；承办人→applyTransfer 生成 FLOW 审批申请。
  - doTransfer 抽出落地逻辑，供「直接流转」和「审批通过」共用。
  - reviewTransfer：同意落地、退回留意见、防串档（申请时阶段≠当前阶段则 STALE 失效）。
  - case_approval 加 flow_action / from_stage 两列（NEW_COLUMNS + schema.sql 同步）。
- **结案扩展 CaseCloseRequestService**（原来是"仅行政、固定四类结果"）：
  - 刑事：WITHDRAW撤案→CANCELLED、TRANSFER_PRETRIAL移送预审→DONE、TRANSFER_OTHER移送其他单位→DONE。
  - 行政：PENALTY处罚/NO_PENALTY不予处罚/TERMINATED终止调查/MEDIATION调解→DONE。
  - 新增 directClose（案管/领导直接结案，不走审批）；review 同意按 outcome 映射状态。
  - 状态映射：撤案→CANCELLED，其余→DONE（用户明确"细分状态"）。

### 前端
- CaseStageBar：canTransfer 去掉 isFullAccess 限制，承办人看到「申请转入」；提交后 flowPending
  显示「状态变更审批中」。doTransfer 提示按身份区分。
- CaseDetailDrawer：结案区域去掉 caseType==='ADMINISTRATIVE' 限制，支持刑事+行政；
  closeOutcomeOptions 按案件类型动态给选项；加「直接结案」按钮+弹窗。
- Dashboard：加「状态变更待审批 N 条」按钮 + flowDlg 审批弹窗（复用 measure 审批模式）。
- DashboardVO/CaseService.dashboard 加 flowPending 计数（与 measurePending 同口径）。

### 新接口
- /watch/flow-approvals/pending（待审批状态变更列表）
- /watch/cases/{id}/flow-pending（本案是否有待审批流转申请）
- /watch/flow-approvals/{id}/review（审批状态变更）
- /cases/{id}/close（案管/领导直接结案）
- 新增 VO：FlowApprovalVO

### 教训/坑
- **编译必须用 tools/jdk8**：系统默认 JDK（21+）会让 Lombok 1.18.30 注解处理器失效，
  报一堆"找不到 getXxx/setXxx"的假错误。`JAVA_HOME=D:/案件指派demo/tools/jdk8` + maven 编译即可。
  maven 在 tools/maven，本地仓库 tools/m2repo，命令：
  `JAVA_HOME=.../tools/jdk8 tools/maven/bin/mvn.cmd -B -o -Dmaven.repo.local=.../tools/m2repo compile`
- **measure_date 是覆盖式单值**（见 2026-10-29 记录），流转 DETAIN 登记拘留、BAIL 覆盖为取保，
  不是两个独立字段。
- 结案和流转都复用「申请→审批」模式，但分别走 case_close_request 表和 case_approval 表
  （approveType=FLOW），审批入口一个在案件详情抽屉、一个在 Dashboard。

## 18:23 三项需求（commit 466e808）

### 需求1：侦查反馈案管员可录
- 案管员（CASE_MANAGER，上一轮加的 isFullAccess 角色）也能提交待办/意见落实反馈。
- 前端 CaseTodoPanel：canSubmit = !isAdmin || isCaseManager；按钮逻辑：
  isAdmin && !isCaseManager → 「查看反馈」，否则 canSubmit → 「提交反馈」。
  user.js 加 isCaseManager getter（role === 'CASE_MANAGER'）。
- 后端 PlanService.checkStdOrAssignee：案管员对民警自建侦查任务也能代录完成反馈
  （原来是「管理层只可查看自建任务」，现在 caseManager 例外放行）。
- 关键认知：TodoService.addFeedback 的 checkOperate 本来就是 isFullAccess 放行，
  所以「案管员能录待办反馈」只需改前端按钮显隐；只有 PlanService 的自建任务限制需要后端改。

### 需求2：简要案情字段

  详情抽屉 descriptions 区加「简要案情」栏（span=2，pre-wrap）。
- 走 CaseSaveRequest.brief / CaseVO.brief / CaseService.save+toVO。

### 需求3：盯办人员序号+人员编号+案件编号

  与 employee_no（内部工号/导入外键）区分。
- AssigneeVO 加 policeSystemNo，CaseService.assigneesOf 从 org_employee 透出。
- WatchDrawer「主办人与盯办人」区块：加序号（idx+1 小圆点）+「人员编号 xxx」弱化展示。

- 员工档案已有 employee_no（工号），新增 police_system_no 是警综对外编号，语义不同。
