## 晚上：案件列表改时间列 + 阶段退回（4d088b9，本地未 push）

### 需求（用户原话）
1. 案件前面的编号意义不大，改为报案/受案时间：导出的案件用受案时间，未受案手工录的警情用报案时间；
   展示时能选时间升序/降序，默认由新到旧。
2. 提交给领导确认的完成，增加「退回」选项，并能加意见。
3. 追加：编号不要自动生成 CA 开头。

### 实现要点

**① 案件时间（新增 `case_info.case_time`）**
- 这是一个**汇总列**：导入件写 `accept_time`，手工建案写「报案时间」（前端可填，留空按保存时刻）。
- 列表、排序都只读它，避免前端做 COALESCE 判断；`acceptTime` 有值即渲染「受案」，否则「报案」。
- 存量回填：`SchemaMigration.backfillCaseTime`，`UPDATE ... SET case_time = COALESCE(accept_time, created_at) WHERE case_time IS NULL`，只补 NULL、幂等。
- 排序：`CaseQuery.sortField` 默认 `case_time`；`buildWrapper` 加分支，**同值再按 created_at 兜一层**（否则同值行在分页间来回跳）。
- 前端 `CaseTable` 的 prop `showCaseNo` → `showCaseTime`，三处调用（CaseList / MyCases / Reminder）同步改；
  文案统一走 `utils/format.js` 的 `caseTimeText(row)`。

**② 编号去掉 CA 前缀**
- `CaseService.generateCaseNo`：`CA-yyyyMMdd-NNN` → `yyyyMMdd-NNN`（如 `20261018-001`）。
- 用户填了的（导入/手填 filingNo）仍以用户为准，自动生成只兜底唯一约束。

**③ 阶段退回（关键设计决策）**
- 接口 `POST /watch/cases/{id}/flow/return`，body `{comment}`，comment 必填。
- **不新增「退回」状态字段**。退回 = 调 `OpinionService.add(caseId, "【阶段退回】" + comment, null, "A")`，
  顺着现有「意见 → 派生待办」链路走：
  - 派生待办时 `flowService.stampStage` 把 flow_stage 打在本阶段；
  - 于是阶段进度**自然从 100% 掉下来**，前端不再显示「待办已办完，确认转入」；
  - 退回记录也天然留在意见列表里，可追溯；民警「我的待办」立刻能看到。
- 若另造一个 `flow_returned` 状态，就得再想「退回后进度怎么算、民警在哪看到、再提交怎么清状态」，
  等于给同一件事做第二套表达。**待办是意见的唯一载体**（既有硬约定），退回正好落在这条链上。
- **循环依赖**：`FlowService → OpinionService → StaffTodoService → FlowService`，
  故用 `@Resource @Lazy` 注入 OpinionService，避免 Spring 启动期成环。

## 深夜：详情可编辑 + 嫌疑人措施带日期 + 待办卡片紧凑化（a1045bd，本地未 push）

### 需求
1. 案件详情的 BOSS 账号要能修改已录入信息、补写案情；
2. 嫌疑人选了强制措施就必须填日期 —— 当前措施 / 措施开始时间 / 下一节点结束时间；

### 实现
**① 详情可编辑**：`CaseDetailDrawer` 头部加「编辑案件」按钮（仅 `isFullAccess`），
直接复用 `CaseFormDialog` 编辑模式 + `:case-id`，`@done` 里 reload 详情并 emit('done')。
**不要再造一套详情编辑表单** —— 建案表单已经支持编辑态，两套必然漂移。

**② 嫌疑人措施**：`case_suspect` 加 `measure` / `measure_start_at` / `measure_end_at`
（SchemaMigration 登记，存量自动补列）；弹窗里选了措施才展开两个时间选择器；
前后端各一道校验（缺开始 / 缺结束 / 结束早于开始都拒）。
改回「未采取」时必须用 `LambdaUpdateWrapper` 显式 set null —— `updateById` 跳过 null，
不清就会留下与措施矛盾的旧时间（与 `CaseService#transfer` 的 clearMeasure 同款坑）。
措施列放在身份证号之后，46% 宽的抽屉里不用横向滚动就能看到。

**③ 待办紧凑化**：按钮从右侧竖排（4×38px）改到卡片底部横排（26px）；
「意见设置」从独占一行并入 `.cf-todo__card-meta` 右侧（`margin-left:auto`，去虚线框）；
内边距收紧。单卡约 170px → 100px。
**关键结构改动**：`.cf-todo__card-actions` 从 `.cf-todo__card-main` 内移到 card 的直接子元素，
同时把 card-main 的闭合标签提前一格 —— 移动这类块要数清楚 `</div>` 个数。
