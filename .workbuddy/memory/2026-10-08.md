## 疑问回答可修订（09:35-10:05，commit adfbefb）

### 为什么不复用 answer()——两条语义必须分开
原 `answer()` 有硬约束「一问一答，回答后不可再改」，那是针对**首次回答**的防刷答设计；
改答是纠错。共用一个入口会互相打架，故新增 `updateAnswer()`（PUT /questions/{id}/answer），
`answer()` 的一问一答约束**保持不变**。

### 关键设计：修订不覆盖首次回答人/时间
新增 3 列 `answer_edited_by / answer_edited_by_name / answer_edited_at`，
`answerBy / answeredAt` **保持首次原样**——覆盖了就抹掉「谁最初答的」，争议时无从追溯。
界面在回答块内常驻标注「（某某 于 X 修订）」。
其他约束：仅管理层（权限下沉 Service）；未回答的不能「修订」（提示直接回答）；
内容未变直接返回不刷痕迹；问题与回答编辑态互斥。

### 坑：日志新旧对照要在 set 之前抓旧值
`logService.log` 里我先 `setAnswer(newText)` 再 `abbrev(q.getAnswer())` → 新旧都显示新内容。

### 【重要澄清】schema.sql 只有一份是真的
`backend/src/main/resources/sql/` 那份是**历史遗留副本**（缺 case_question 等表），
pom.xml 注释明确写「此前 resources/sql/schema.sql 是手动拷贝的副本，两份会漂移」，
现已改为**根 `sql/schema.sql` 直接映射进 classpath**（application.yml 用
`classpath:sql/schema.sql`）。**改表只改根目录那份**，改副本不仅无用还会制造新漂移。
（我这次先改了两份、发现副本没有该表才确认，属多余动作。）

## 信箱「查看案件」精确定位 + 高亮（09:48-10:15，commit 8b9b6e9）
用户要求点信件直达具体内容（任务/疑问/回答）+ 短暂高亮 + 目标不存在时降级。

### 前提：日志里没有目标 id，锚点必须业务侧显式传
`operation_log.targetId` **统一是 caseId**，不带 todoId/questionId；
日志正文是拼接文本（如"回答疑问：xxx → xxx"）无法反查。
故：`LogService.Anchor` 值对象 + `logAnchored(...)` 重载（**不污染既有 8 参签名**，
把原 log 主体抽成私有 `write(...)`，旧重载全部转调它），
通知表加 anchor_todo_id / anchor_question_id / anchor_subtask_id。
**这套「定位锚点」是通用模式**：任何"从消息跳到具体内容"的需求都要靠它，
光有 caseId 只能跳到页面级。

### 覆盖的埋点 10 处
疑问 ask/answer/updateAnswer/update/remove → `ofQuestion(todoId, questionId)`
待办 add/done/delete/feedback/subtaskAdd → 主任务 `ofTodo`、子任务 `ofSubtask(parentId, id)`

### 定位链路与两个关键细节
路由 `?caseId&todoId&questionId&subtaskId` → 页面 consumeOpenCase → CaseDetailDrawer(anchor)
→ CaseTodoPanel(anchor) → TodoDetailDialog.openAt(id, anchor) → 定位+高亮。
1. **锚点用属性选择器**（`data-cf-qid`/`data-cf-subid`），**不用 nth-child**——
   列表会随反馈/排序增删，nth-child 会指错行。
2. **先展开再等渲染再滚**：疑问区默认折叠，`qExpanded=true` 后要 `nextTick` +
   短延时，否则列表还没渲染、scrollIntoView 滚不到。
3. 定位参数**用完立即从地址栏抹掉**（caseId 一并抹），否则刷新重复定位。

### 高亮
CSS 动画 `cf-flash`（黄底 #fff3cd + 橙描边 → 淡出），2.6s 后 JS 移除 class。
**禁用悬浮提示的项目约定下，"高亮"比"角标/提示"更符合"快速识别目标"的需求。**

### 三级降级（静默，不报错不白屏）
1. 无 todoId（存量通知/案件级操作）→ 只开案件详情
2. todoId 查不到 → 提示"该任务已被删除"，停在案件详情
3. questionId/subtaskId 查不到 → 浮窗照常开，只是不高亮
**跳转是辅助功能，不该因目标消失而中断。**

## 工作台排版优化（10:03-10:20，commit 29b06d4）
用户反馈工作台「7 天内到期 + 最近操作」区域难看。三个真实问题：

### 1. 表格列被挤断 → CaseTable 加 compact 模式
全列宽合计约 1156px（150+220+140+70+150+190+86+150），span16 容器放不下，
浏览器把「截止期限」压扁成`2026-09-18（剩 1…`。
**窄栏位只留 5 列**（案件名称/主办协办/截止期限/状态/操作），
编号、案件类型、嫌疑人挪到完整列表（案件管理）看。实测 clientW==scrollW==770。

### 2. actionName 漏映射 → 界面直接显示英文
`OperationLogService.actionName` 的 switch 没覆盖后加的模块，
疑问/待办系列全部走 default 原样返回英文（QUESTION_ASK 等），工作台一眼看到英文。
**加新模块时必须同步在 actionName 补 case，否则界面漏出英文 action 名。**
已补 30+ 条（疑问 5 / 待办 8 / 意见扩展 5 / 转手审批 4 / 账号 4）。

### 3.【坑】同排等高不能用 flex:1 + height:100%（又踩一次循环依赖）
第一次用 `el-col{display:flex} + .cf-panel--fill{flex:1}` 想让两面板等高，
结果面板被撑到 **1289px**（整页高）——高度反过来依赖列高，成 flex 循环依赖。
**正解：给两个面板一个确定的固定高度**（346px = 头 44 + 页签 38 + 内容 262），
各自吃准同一个值，底部自然齐平。
**`cf-panel--fill` 只适用于「父级高度本身已确定」的场景**；
父级高度由内容决定时用它就是自指。判断标准：先看父级有没有确定高度，
没有就别上 fill/flex:1。
