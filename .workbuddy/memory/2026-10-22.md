## 晚 19:15 升降级安全加固 + 重新出部署包

领导要求（转述）：
1. **每次提交就重新提交一个部署包** → 以后固定动作，不再等用户开口要
2. **数据结构千万不能改动**
3. **部署时不要影响内网已录入的数据**

### 做了什么

**A. 数据整理加一次性闸门（核心）**
`SchemaMigration` 原来每次启动都会跑 6 处数据改写，其中 4 处会**覆盖已有值**：
`retireStdPlanTasks`（把模板任务置 CANCELLED）、`removeCivilType`（把 CIVIL 案件
清成未分类）、`migrateCategory`、`migrateLegacyDeadlineReceipts`。

现在：
- 新增内部表 `schema_migration_mark(mark_name PK, applied_at)`（只记录，与业务无关）
- `onceOnly(conn, name)` 闸门：执行前查台账，跑过就跳过；**台账写不进去就不执行**
  （宁可少整理，也不反复改数据）
- 4 处覆盖型整理全部套闸门 → 一个库一辈子只跑一次
- `removeCivilType` **改成只 SELECT COUNT 写 WARN**，完全不再改数据
  （原逻辑会把用户选过的案卷类型抹掉，与"不动已录入数据"直接冲突）
- 只补空值的（`backfillCaseTime` / `seedCategories` / `backfillFeedbackDeclare` /
  `migrateSingleDeadlineToTimeNodes`）保持每次跑，天然幂等

**B. 结构与数据安全边界（正式定为纪律）**
- 结构只允许：`CREATE TABLE IF NOT EXISTS`、`ALTER TABLE ADD COLUMN`（可空或带默认）
- 禁止：DROP / RENAME / MODIFY COLUMN / TRUNCATE（`schema.sql` 与
  `SchemaMigration` 已 grep 验证为 0）
- 业务数据只允许补 NULL、不允许覆盖非空值（覆盖型一律进闸门）

**C. 文档同步**
- `package_portable.py#UPGRADE_TXT` 增加「数据结构会不会被改坏？已经录进去的数据会不会动？」
  整节，明确"只加不删、不改类型、不改表名；数据原样保留"
- `docs/manual-v3/部署教程.md` + HTML + 重新生成的 `部署教程.docx` 同步该章节
  （html-review 100 分，导出零警告）

## 19:40 嫌疑人信息支持修改（commit 4dda88b）

### 改了什么
- `CaseDetailDrawer.vue` 嫌疑人表格操作列：`60px` 只有「删除」→ `104px` 加「修改」。
  新增/修改复用同一个弹窗，标题按 `suspectEditingId` 切换；日期回显统一走 `dateKeyOf`。
- **修掉一个真 bug**：措施下拉清空后 `v-model` 是 `undefined`，`{...f}` 展开后
  JSON 里字段直接消失 → 后端 `applyMeasure` 把「字段不存在」当成「这次不改措施」
  → 用户清了措施、保存后还在。提交前对措施三列显式兜底（`''` / `null`）。

### 验证
新增 `scripts/cf-e2e-suspect-edit.mjs`（28 项断言，自造自删测试数据）：
入口 → 弹窗标题 → 6 个字段回显 → 只改电话保存 → 姓名/身份证/措施不被连带改动
→ 抽屉表格即时刷新 → 措施改回「未采取」时间清空。全绿，控制台零错误。

### 坑（下次照抄）
- **案件列表已经没有「编号」列了**（2026-10-22 换成了「报案/受案时间」）。
  e2e 脚本想按案号定位行会拿不到表头；改用「嫌疑人」列文本做锚点。
- Element Plus 的 `.el-select__clear` 是 **v-if + hover 才渲染**，
  直接 `querySelector` 拿到 null；必须先用 `p.mouse.move` 真的移进下拉框再找。
- `el-select` 清空后值是 `undefined` 而不是 `''`——凡是要"清空即落库"的字段，
  提交前都得显式兜底，否则 JSON 丢字段会让后端误判成「不修改」。
