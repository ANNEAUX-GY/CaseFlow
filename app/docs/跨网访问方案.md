# 跨网访问方案（手机 / 外网访问这套系统）

> 背景：本机的局域网地址 `http://192.168.2.118:8080/api/` 在电脑上能打开，**手机连同一个 WiFi 却打不开**；
> 并且希望不只是局域网内能用，出差、在家、手机上也要能看案件。
>
> 结论先给：**打不开是 Windows 防火墙没放行 8080，不是系统的问题**。跨网则按「能不出公网就不出公网」的顺序选方案。

---

## 0. 为什么电脑打得开、手机打不开

这是最容易被误判的一类问题。原因是 Windows 防火墙**拦入站、放行出站**：

| 谁在访问 | 流量方向 | 结果 |
|---|---|---|
| 本机浏览器访问 `127.0.0.1:8080` | 回环，不过防火墙 | ✅ 通 |
| 本机浏览器访问 `192.168.2.118:8080` | 本机自己发给自己 | ✅ 通（**所以自查永远是通的**） |
| 同事电脑 / 手机访问 `192.168.2.118:8080` | 入站 | ❌ 被防火墙丢弃 |

本机实测到的现状（2026-09-30）：

```
网络类型：WLAN -> Public（公用网络，入站默认拦截最严）
防火墙  ：Domain / Private / Public 三个配置全部 Enabled
放行规则：无（netsh 查询 "CaseFlow 8080" 返回"没有与指定标准相匹配的规则"）
```

> 关键教训：**不要用"本机能打开"证明服务没问题**。判断服务是否对局域网开放，必须从另一台设备访问，或者直接查防火墙规则。

### 修复：以管理员身份运行

```
scripts\open_lan_firewall.py
```

（在 PyCharm 里可直接选运行配置「⑩ 开放局域网访问（需管理员）」，
脚本会自动弹 UAC 授权窗口。）

脚本做的事（就两件，不多改一个字）：

1. 新增入站规则 `CaseFlow 8080`：放行 TCP 8080，`profile=any`（不分公用/专用网络都生效）
2. 把当前局域网地址和二维码打印出来，手机直接扫

它**不会**关闭防火墙、不会开 8080 以外的任何端口、不注册系统服务。想收回权限执行：

```
python scripts/open_lan_firewall.py --remove
```

或者直接调 netsh：

```
netsh advfirewall firewall delete rule name="CaseFlow 8080"
```

> 如果这台电脑由单位统一管控（组策略下发），`netsh` 可能被拒绝。这种情况必须找 IT 代为放行 TCP 8080 —— 这是正规做法，不要试图绕过。

## 1. 四种跨网方案对比

> 所有方案都只是**网络通道**：把手机/外网的请求转发回这台电脑的 8080。
> 后端还是那一个后端，数据库还是那一个 MySQL —— 所以**不存在"数据同步延迟"这回事**，看到的就是同一份数据。
> 差别只在**延迟、带宽、是否需要暴露公网、以及数据经过谁的手**。

| | ① 局域网直连 | ② Tailscale / ZeroTier | ③ cpolar 内网穿透 | ④ 单位 VPN / 政务网 |
|---|---|---|---|---|
| 现在能否用 | 放行防火墙即可 | 装客户端即可 | 装客户端即可 | 需向 IT 申请 |
| 使用范围 | 同一个 WiFi | **任意网络**（4G/家里/出差） | **任意网络** | 单位网络内 |
| 数据路径 | 不出局域网 | 端到端加密，点对点直连；打洞失败才走中继 | **经第三方服务器中转** | 单位自有通道 |
| 预期延迟 | 2–10 ms | 直连 20–60 ms / 中继 80–200 ms | 100–300 ms | 依单位网络 |
| 带宽 | 局域网带宽 | 不限速（走你的宽带上行） | **免费版 1 Mbps**；基础版约 29 元/月 3 Mbps | 依单位网络 |
| 手机要装东西吗 | 不用，浏览器直接开 | 要装 App（iOS/Android 都有） | 不用，浏览器直接开 | 可能要装 VPN 客户端 |
| 地址是否固定 | 会变（换 WiFi/重启路由就变） | **固定**（MagicDNS 域名） | 免费版每 24 小时换一次 | 通常固定 |
| 安全性 | 最高 | 高 | **最低（公网可达）** | 高 |
| 适合 | 日常办公 | **推荐：长期、自己人用** | 临时演示、给外人看 | 单位正式上线 |

### 我的建议顺序

1. **先把防火墙放行**（第 0 节）—— 这一步解决你截图里的问题，且零成本。
2. **日常跨网用 Tailscale**：同样是"自己人用"，但不用把服务暴露到公网，速度和隐私都更好，地址还固定。
3. **cpolar 只用来临时演示**（比如给外单位的人看一眼）。它把系统挂到公网，**上线前必须先做第 2 节的安全加固**，否则等于把办案数据放到了互联网上。
4. **正式上线一定走第 ④ 条**：单位已有 VPN / 政务外网 / 域名映射的话，那才是最合规、最省心的路。

## 2. cpolar 上线前必须做的安全加固

cpolar 免费版把系统直接暴露到公网，任何人只要拿到那个随机域名就能看到登录页（免费域名还是 24 小时换一次，等于每天都在换新的暴露面）。**当前代码里有几处是演示级的，必须先收掉**：

| 项 | 现状 | 必须改成 |
|---|---|---|
| Token 可从 URL 参数传 | `?token=xxx` 可以（用于附件下载） | 附件下载改用**一次性短票据**，或改成 POST + Header；URL 里的 token 会进 cpolar 的访问日志和手机浏览器历史 |
| 密码强度 | 只校验 ≥ 6 位 | 至少 8 位 + 复杂度；管理员账号强制 12 位 |
| 登录失败次数 | 不限制 | 同账号/同 IP 连续失败 5 次锁定 5 分钟（防爆破） |
| h2-console | dev 下开启 | 生产必须关闭（当前已只放行 `/h2-console/**`，MySQL 模式下不存在，但要确认） |
| CORS | `allowedOriginPatterns("*") + allowCredentials` | 只允许自己的域名 |
| 附件下载 | 只要 token 有效就能下 | 记 `operation_log`，谁在什么时候下载了哪份材料 |
| 传输 | HTTP 明文 | cpolar 免费版会给一个 HTTPS 域名，**务必用 https 那个地址** |
| 访问控制 | 无 | cpolar 后台「访问控制 → 密码保护」加一层，或升级到商业版用 IP 白名单 |

> 一句话：**系统里全是案件材料，cpolar 只当临时演示用，别当生产通道。**

## 3. Tailscale 具体怎么落地（推荐方案）

Tailscale 免费版（Personal）：**3 个用户、100 台设备**，长期免费。
对你们这个场景完全够用 —— 一台电脑当服务端 + 若干台手机/笔记本，它们都登同一个 Tailscale 账号即可。

### 服务端（这台电脑）

1. 到 tailscale.com 下载 Windows 客户端，安装并登录（需要一个邮箱账号，建议用单位邮箱注册）。
2. 登录后在系统托盘看到本机的 Tailscale IP（形如 `100.x.y.z`）和机器名（形如 `caseflow-pc`）。
3. 手机端装 Tailscale App，登**同一个账号**。
4. 手机上直接打开：

```
http://100.x.y.z:8080/api/          # 用 IP
http://caseflow-pc:8080/api/        # 或用 MagicDNS 机器名（更好记）
```

> 注意：**地址结尾的 `/api/` 不能少**（后端 context-path 就是 `/api`）。
> 另外 Tailscale 自己的接口（`login.tailscale.com`）在国内可访问但不总是稳定；打洞成功时是点对点直连、速度和局域网接近，打洞失败会走香港/东京的中继，会慢一些但通常能用。**先在办公室试通再推给同事用。**

### 两个必须注意的点

- **装 Tailscale 需要管理员权限**。当前这台电脑的会话不是管理员，运行安装包时系统会弹 UAC，需要管理员账号同意。
- **Tailscale 网段是私有的**：只有加入你 tailnet 的设备能访问，公网扫不到。这也是它比 cpolar 更适合长期使用的原因。

### 如果 Tailscale 不稳定

- **ZeroTier**：同类产品，支持自建 Moon 节点加速（国内常用这套绕过中继慢的问题）。
- **自建 frp + 一台有公网 IP 的云服务器**：最可控，延迟取决于云服务器位置（国内节点通常 30–80 ms），但要自己维护，且云服务器本身也要做安全加固。
- **cpolar 付费版**（基础版约 29 元/月，3 Mbps）：省事，但依然是公网暴露 + 第三方中转。

## 4. 关于"响应速度和数据更新速度"

你的顾虑可以放心，理由如下。

**数据新鲜度：三种方案完全一样。** 它们都只是把请求转发回同一台机器上的同一个 Spring Boot 进程、同一个 MySQL 库。不存在"同步一份数据过去"这种事，任何一次指派、改期限、办结都是**直接写主库**，对方刷新就能看到。真正的"同步延迟"只会出现在多库/多节点复制架构里，那正是我们**刻意没做**的东西（见 `docs/生产化改造指南.md`：50 人以内单实例足够，不要上集群）。

**速度差异只在网络这一段。** 实测参考（首次打开页面）：

| 通道 | 首屏 | 之后翻页 |
|---|---|---|
| 局域网 | 飞快（<1 s） | 飞快 |
| Tailscale 直连 | 1–2 s | 流畅 |
| Tailscale 中继 | 2–4 s | 可用 |
| **cpolar 免费（1 Mbps）** | **约 6–8 s** | 缓存后流畅 |

cpolar 免费版慢的原因很具体：前端打包后 **gzip 后约 750 KB**，1 Mbps ≈ 125 KB/s，除下来就是 6 秒左右。**第一次打开慢，浏览器缓存之后就好了**，但首次体验会让人以为"系统很卡"。基础版（3 Mbps）能把这个压到 2 秒出头。

**再加一条**：手机首次打开慢，还和 App 里的图表（ECharts，本身就 1 MB 级）有关。如果以后要专门优化手机端，可以把图表页做成按需加载 —— 但这属于优化，不是现在的瓶颈。

## 5. 顺手解决两件会影响日常使用的事

### 5.1 同一账号现在可以多端在线（已改）

改动前每个账号同一时刻只能有一个登录态：**你手机上登录，电脑上的登录就被踢下线**。手机访问一开始会很别扭。现在已经改成同一账号最多保留 5 个会话（电脑 + 手机 + 平板），超出才挤掉最早的那个；停用/删除账号时会立刻把该账号所有会话踢下线。

### 5.2 局域网 IP 会变，别把它写进纸质说明

本机的局域网地址已经变过一次（`192.168.2.118` → 现在默认路由是 `10.169.37.241`，另有一个 `172.24.112.1` 是虚拟网卡）。换 WiFi、路由器重新分配、休眠唤醒都可能变。

- 局域网用：让 IT 给这台机器**绑定静态 IP**（MAC 绑定），或者在路由器上设 DHCP 保留。
- 跨网用：**Tailscale 的 MagicDNS 机器名天生固定**，这也是它比"记 IP"省事的地方。
- 打印操作手册时，只用 `scripts/start_lan.py` 启动时打印/生成二维码的那个地址，不要手写死。

## 附：启动脚本现在会做什么

```
.venv\Scripts\python.exe scripts\start_lan.py --detached
```

启动完成后会打印：

- 本机访问地址 + 局域网访问地址（默认路由那个放最前）
- **手机扫码用的二维码**（终端直接画出来，不用手输 IP）
- 防火墙自检：没放行 8080 时会明确提示"症状：本机能打开，手机打不开"并给出脚本路径
- MySQL 会自动拉起（没在跑就启动）
