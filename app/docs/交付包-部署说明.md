# CaseFlow 案件指派系统 · 部署说明（傻瓜版）

> **看不懂这一页，就直接双击【启动.bat】。**
> 数据库口令没填时，系统会自动走「试用模式」，不需要装数据库就能先跑起来。

---

## 零、怎么开始（三步）

1. 把 zip **完整解压**到 `D:\CaseFlow` 这样的目录
   （不要在压缩包里直接双击，必须先解压）
2. 双击 **【启动.bat】**，等 30 秒
3. 浏览器打开 **http://localhost:8080/api/**
   （试用模式是 **http://localhost:8099/api/**）

登录账号：

```
账号：boss
密码：admin123
```

> 登录后请**立刻**到「账号管理」改掉密码。

**就这样，系统已经能用了。**下面这些是给要做正式部署、或出问题时看的。

## 一、试用模式 vs 正式模式

启动时系统会自己判断，不需要你选：

| | 试用模式 | 正式模式 |
|---|---|---|
| 触发条件 | 口令还是中文提示（没填） | 口令已改成真实口令 |
| 要装 MySQL 吗 | **不用** | 要 |
| 数据库 | 内置，文件在 `data\h2` | MySQL |
| 访问端口 | 8099 | 8080 |
| 适合 | 先试试看、单机少量用 | 正式多人使用 |
| 数据备份 | 直接复制 `data` 目录 | 导出数据库 + 复制 `data` |

> 试用模式适合**先看看系统长什么样**。真正给单位用，请务必配 MySQL：
> 试用模式是单文件数据库，多人同时提交时容易变慢，也没法做精细备份。

## 二、配置正式数据库（正式使用必做）

### 第 1 步：装 MySQL 8.x

如果这台电脑还没有 MySQL，把下面这段**发给懂技术的同事**：

```sql
-- 1. 建库
CREATE DATABASE case_flow DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- 2. 建账号（把 '换成您自己的强口令' 换掉，别用弱口令）
CREATE USER 'caseflow'@'localhost' IDENTIFIED BY '换成您自己的强口令';
GRANT ALL PRIVILEGES ON case_flow.* TO 'caseflow'@'localhost';
FLUSH PRIVILEGES;
```

### 第 2 步：填口令

用记事本打开 `config\application-prod.yml`，找到：

```
    password: 请改成你自己的数据库口令
```

把中文替换成上一步设的强口令，保存。

**这是整个部署过程唯一需要改的地方。**

### 第 3 步：建表（只需做一次）

用 Navicat / DBeaver / MySQL Workbench 等工具，对 `case_flow` 库执行
「运行 SQL 文件」→ 选 `建库脚本\schema.sql`。

成功后库里会出现 **22 张表**（其中 `schema_migration_mark` 是程序自用的记录表，不用管）。

> 这一步**只在新装的机器上做一次**。以后升级不用再跑（原因见第六节）。
> 万一漏了某张表也不用慌：程序启动时会自动补建、自动补列。

命令行也可以：

```
mysql -u caseflow -p case_flow < 建库脚本\schema.sql
```

### 第 4 步：重新启动

双击【停止.bat】，再双击【启动.bat】。这次窗口里显示的端口是 **8080**。

## 四、常见问题

### Q1：同事打不开网页

按顺序排查：

1. **黑色窗口还在吗？** 关了 = 服务停了，重新双击【启动.bat】
2. **防火墙**：以**管理员身份**双击 `放行防火墙.bat`
3. **网络类型**：设置 → 网络和 Internet → 属性 → 改成**专用网络**（公用网络会拦）

### Q2：启动时报「数据库连不上」

1. MySQL 服务启动了吗？Windows 里搜"服务" → MySQL → 启动
2. `config\application-prod.yml` 里的**密码填对了吗**（最高频原因）
3. 口令里有 `#` `:` 等特殊字符吗？→ 换成纯字母数字
4. 数据库建了吗？表建了吗？（见第二节第 1、3 步）

### Q3：提示端口被占用

说明服务已经在跑了。双击【停止.bat】再启动。

确实是别的软件占用：记事本打开 `启动.bat`，把里面的 `set PORT=8080`
改成别的数字，访问时端口也要跟着改。

### Q4：窗口一闪而过 / 马上关掉

双击 `启动.bat` 时如果闪退，说明启动器本身有问题。
在 `cmd` 里进入本目录后执行 `启动.bat`，就能看到停留的错误。

### Q5：忘记密码

管理员登录后到「账号管理」重置。

### Q6：能存多大的附件

单文件 50 MB，单次请求 100 MB。

## 五、数据备份（**最重要，请定期做**）

有两样丢了**无法重建**：

| 什么 | 在哪 | 怎么备份 |
|---|---|---|
| 业务数据（正式模式） | MySQL `case_flow` 库 | `mysqldump` 导出 |
| 业务数据（试用模式） | `data\h2` 目录 | 整个 `data` 目录复制走 |
| 附件材料 | `data\uploads` 目录 | 整个目录复制走 |

每日自动备份示例（需懂技术的同事配置"任务计划程序"）：

```bat
mysqldump -u caseflow -p case_flow > D:\backup\caseflow_%date:~0,8%.sql
robocopy D:\CaseFlow\data\uploads D:\backup\uploads /MIR
```

> **一定要实际演练过一次恢复**。没验证过的备份等于没有备份。

## 六、升级到新版本（内网更新必读）

> 一句话：**换程序，不动数据**。新包解压后覆盖进去，你单位已经录进去的案件、
> 嫌疑人、附件、待办、领导意见、审批记录，一条都不会被改掉。

### 6.1 三条铁律

1. **只覆盖 `case-flow-backend.jar` 这一个文件**
   （`runtime\` 是自带的 Java，一般不用换；`config\`、`data\`、`建库脚本\` **不要覆盖**）
2. **`data\` 目录一个文件都不要动**
   附件在 `data\uploads`；**试用模式下整个数据库就在 `data\h2`**
3. **不要重新执行 `建库脚本\` 里的 SQL**
   新版本需要的列由程序启动时**自动补齐**，跑脚本对已存在的表不起作用；
   `index-mysql.sql` 更是只在首次建库后执行一次，重复执行会报
   `Duplicate key name`（不影响数据，但会让人误以为升级失败）

### 6.2 四步升级（正式模式 / MySQL）

| 步 | 做什么 | 怎么确认做对了 |
|---|---|---|
| 1 | **备份**：`mysqldump -u caseflow -p case_flow > D:\backup\升级前.sql`，再复制一份 `data\uploads` | 备份文件大小不是 0 |
| 2 | 双击 **【停止.bat】** | 浏览器打不开 8080 |
| 3 | 用新包的 `case-flow-backend.jar` **覆盖**旧文件 | 文件修改时间是今天 |
| 4 | 双击 **【启动.bat】**，等 30 秒 | 浏览器能打开、能登录、案件数没变 |

升级**不需要**停 MySQL、**不需要**执行任何 SQL。

### 6.3 试用模式（H2 单文件库）额外注意

试用模式的数据库就是一个文件：`data\h2\caseflow.mv.db`。

- 升级前把**整个 `data` 目录**复制一份（这就是全部数据）
- **必须原地覆盖**：把新包解压到旧目录上。千万不要解压到另一个新目录再启动——
  那样程序会建一个空库，看起来像"数据全丢了"（其实旧库还在老目录里，没丢）

### 6.4 升级会做什么、绝不会做什么

**会做的（都是在"补"，不删不改已填的内容）：**

| 动作 | 举例 |
|---|---|
| 给老表补新列 | 老库没有 `case_info.case_time`、`case_suspect.measure` 这类列，启动时自动加上（可空，不动已有行） |
| 补空值 | `case_time` 为空的行按「受案时间，没有就按录入时间」填上 |
| 首次补齐类别字典 | `case_category` 空表时写入 13 条默认小类 |
| 老的单期限转成多时间节点 | 把 `case_info.deadline` 派生成 `case_time_node` 一条节点（**原来三列保留不动**） |
| 落实说明拆列 | 老记录里的「于 X 在 Y 执行了 Z 操作。」拆成 时间/平台/操作 三列，界面上会拼回同一句话，信息不丢 |
| 记一条内部台账 | 保证下面这些历史整理**一辈子只做一次**，以后每次升级直接跳过 |

**绝不会做的：**

- ❌ 删表、删列、改列类型、改表名
- ❌ 修改已录入的案情、嫌疑人、附件、待办、领导意见、审批记录
- ❌ 清空、重置任何业务表
- ❌ 每次启动重复跑历史数据整理（有一次性闸门：`schema_migration_mark` 记过就不再跑）
- ❌ 把已经填过的值改成别的值（只补 `NULL`）

> 这些不是口头承诺，是代码里的硬约束：`schema.sql` 全文只有
> `CREATE TABLE IF NOT EXISTS`，迁移类只做 `ALTER TABLE ADD COLUMN`，
> 全文没有一句 `DROP` / `MODIFY` / `RENAME` / `TRUNCATE` / `DELETE`。

### 6.5 升级后自检三条

1. 登录后「我的案件」件数与升级前**一致**
2. 随便点开一个案件，待办、领导意见、附件都还在
3. 打开 `logs\console.log`，搜 `ERROR`：没有就正常。
   出现「`[SchemaMigration] 已补列：xxx`」是**正常**的，说明新列补上了

### 6.6 万一要回退

停服 → 换回旧 `jar` → 启动。**新增的列留着不影响旧版本**（旧版本只是不看它们），
所以绝大多数情况直接换回 jar 就能跑；如果还想彻底回到升级前，用第 1 步的备份恢复数据库。

## 七、这个文件夹里都是什么

```
CaseFlow\
├─ ★ 先看我.txt           ← 最快的上手方式（3 步）
├─ 启动.bat              ← 平时只用这一个
├─ 停止.bat
├─ 放行防火墙.bat        ← 同事打不开时用（需管理员身份）
├─ 部署说明.md            ← 就是这份
├─ 使用教程\              ← 给用系统的人看，含截图
│   ├─ 使用教程.md
│   └─ shots\（界面截图）
├─ case-flow-backend.jar ← 程序本体
├─ runtime\              ← 自带的 Java，不用管，也别删
├─ config\               ← 配置文件（填口令改这里）
├─ 建库脚本\             ← 首次部署执行一次
├─ data\                 ← 数据，必须备份
└─ logs\                 ← 日志，出问题看这里
```

## 八、还不行怎么办

把这三样发给技术支持，一次就能定位：

1. `logs\console.log` 的**最后 20 行**
2. 这台电脑的 Windows 版本（设置 → 系统 → 关于）
3. 启动时黑窗口里显示的**完整报错文字**
