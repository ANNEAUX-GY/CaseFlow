## 第 1 章 系统概览与技术栈

### 1.1 系统做什么

面向派出所的案件流转管理系统：**建案 → 指派 → 领导提意见（自动派生待办）→ 承办人反馈完成 → 办案阶段流转**。

## 第 4 章 开发环境启动

### 4.1 一键启动（推荐）

```bash
# 前提：cd 到 app/ 目录
.venv\Scripts\python.exe scripts\dev.py --seed
```

访问：前端 `http://127.0.0.1:5173`　后端 `http://127.0.0.1:8080/api`　H2 控制台 `http://127.0.0.1:8080/api/h2-console`

### 4.2 `dev.py` 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--profile {dev,mysql}` | `dev` | 数据库 profile |
| `--no-frontend` | | 只启动后端 |
| `--no-backend` | | 只启动前端（不碰后端、不做端口/H2 检查） |
| `--seed` | | 启动后等 3 秒灌演示数据 |
| `--backend-port` | `8080` | 同时注入 `CF_SERVER_PORT`、传给 Maven、写进前端 `VITE_BACKEND` |
| `--skip-db-check` | | mysql profile 下跳过本地实例探测（连外部库时用） |
| `--kill-existing` | | 端口被占时 `taskkill /F /PID` 后再启动 |
| `--check` | | **只做 5 项环境自检，不启动服务** |
| `--fix-deps` | | 修 Python venv + 前端 node_modules 后退出 |

### 4.3 `dev.py` 启动流程与其中的坑

1. `--fix-deps` / `--check` 直接分流返回
2. 端口探测：dev 模式下端口被占**直接报错退出**（**H2 文件库独占，换端口也没用**）；mysql 模式自动 `find_free_port(port+1)`
3. `h2_file_locked()`：以 `open(db, "r+b")` 探测独占，被锁则报错退出
4. `find_jdk()` → 设 `JAVA_HOME` / `PATH` / `SPRING_PROFILES_ACTIVE` / `CF_SERVER_PORT`
5. mysql profile 且未 `--skip-db-check`：`ensure_local_mysql()` 拉起本地 mysqld 并注入连接参数
6. `strip_port_env(env)`：**删除 `SERVER_PORT` / `SERVER__PORT` / `PORT` 环境变量**
7. `mvn -B -Dmaven.repo.local=tools/m2repo -Dspring-boot.run.arguments=--server.port=X spring-boot:run`
8. `wait_backend()` 轮询 `http://127.0.0.1:PORT/api/auth/roles`，**超时 180 秒**
9. 启动前端（依赖非 ok 时自动 `npm install`）
10. `--seed` → `seed_demo.py`
11. 死循环，Ctrl+C 时 terminate 所有子进程

**⚠️ 健康检查地址必须是 `/api/auth/roles`。** `dev.py:31-40` 有长注释记录踩坑史：原写 `/api/auth/dict`，但 `WebConfig` 后来把 `/auth/**` 整体放行收窄成逐个列举，`/auth/dict` 不在名单 → 未带 token 会 401 → 空轮询 180 秒 → 误报「后端启动失败」。

**⚠️ 依赖修复用 `npm install` 而非 `npm ci`。** `npm ci` 会先清空 `node_modules`，重建中 `node.exe` 被占用会 EBUSY，把可用目录砸成半成品。

### 4.4 手动分别启动（不推荐）

```bash
# 后端（必须在 app/backend 目录！）
cd backend && ..\..\tools\maven\bin\mvn.cmd -Dmaven.repo.local=../../tools/m2repo spring-boot:run

# 前端
cd frontend && npm run dev
```

### 4.5 ⚠️ 后端工作目录：最容易踩的坑

`application-dev.yml` 的 `jdbc:h2:file:./data/h2/caseflow` 是**相对路径，按进程工作目录解析**。

| 启动目录 | 结果 |
|---|---|
| `app/backend/` | ✅ 打开 `app/backend/data/h2/caseflow.mv.db`（真库） |
| **仓库根** | ❌ **静默新建一个空库**（根目录冒出 `data/h2/caseflow.mv.db`） |

在错误的目录启动，真库毫发无损但**接口全是 0 条**，表现为「案件全没了 / audit 报 0 条 / verify 各种 400」。

**排查步骤**：

1. `ls data/h2/` 看根目录有没有多出库 —— **多出来的空库就是元凶**
2. 看 `app/backend/data/h2/caseflow.mv.db` 的 mtime 是否变过 —— 没变 = 真库安全

> `mvn spring-boot:run` 的工作目录是 `app/backend`，所以日常开发没问题。**手动 `java -jar` 时必须自己保证 `cd app/backend`。**

### 4.6 PyCharm 运行（用户硬要求必须支持）

- `D:\PyCharm 2026.1.2\bin\pycharm64.exe`，**必须打开 `app` 目录**（开上一级读不到工程配置）
- `.idea/vcs.xml` 已配 Git 映射到上一级
- `.idea/runConfigurations/` 内置 **10 个带序号配置**，统一：

  - `WORKING_DIRECTORY = $PROJECT_DIR$`
  - **`EMULATE_TERMINAL = true`** ← **不开则子进程输出被缓冲，看着像卡死**
  - `PYTHONUNBUFFERED=1`、`PYTHONIOENCODING=utf-8`
- 10 个配置：一键启动(①`--seed`)、只后端(②)、只前端(③)、环境自检(④)、修复依赖(⑤)、灌演示数据(⑥)、一致性体检(⑦)、打包成品(⑧)、局域网部署启动(⑨)、开放防火墙(⑩)

- **本机专属忽略规则写 `.git/info/exclude`**，不要改仓库里的 `.gitignore`（否则会推给队友造成漂移）

## 第 5 章 构建与打包

### 5.1 ⚠️ 编译顺序（真踩过）

```
先 taskkill 掉 8080 的 LISTENING 进程 → 再 package → 再启动
```

`mvn package` 被运行中的后端占住 jar 时，repackage 会报 `Unable to rename ...jar to .jar.original`，**在 `-q` 下几乎看不出**，表现是「打包成功了但 jar 是旧的」。

> **停后端只杀 8080 的 LISTENING 进程**——按 `:8080` 宽匹配会连带杀掉 Vite 的 ESTABLISHED 连接。

### 5.2 后端打包

```bash
JAVA_HOME=tools/jdk8 \
MAVEN_ARGS="-o -Dmaven.repo.local=D:/盯办/CaseFlow开发环境包/tools/m2repo -DskipTests" \
tools/maven/bin/mvn.cmd -q -f app/backend/pom.xml package
```

产物：`app/backend/target/case-flow-backend.jar`（约 72.7 MB）

> PowerShell 调 `mvn.cmd` 会拆分含 `.`/`=` 的参数，**必须用 `MAVEN_ARGS` 传参**；PowerShell 工具不回显 stdout。

### 5.3 前端构建

```bash
cd app/frontend
# 用托管 Node：
node.exe node_modules/vite/bin/vite.js build
# 或 npm run build
```

产物 `dist/` 约 2.5 MB（gzip 750KB~1MB），约 12 秒。

> **不能把 `node.exe` 直接当脚本跑**（`node.exe build` 是错的）。
> **不要跑 `npm ci`**：会被 safe-delete 拦，且它会先清空目录。需要修依赖用 `npm install --include=optional`。

### 5.4 打包脚本

| 脚本 | 产物 | 参数 |
|---|---|---|
| `package_release.py` | `app/backend/target/case-flow-backend.jar`（前端已内嵌 `static/`） | `--skip-frontend` `--no-clean` |
| `package_source.py` | `release/caseflow-source-<版本>[-时间戳].zip` | `--out` `--no-data`（不含演示库）`--wx`（纯 ASCII 文件名 + 顶层包一层目录）`--compress` |

`package_source.py` 的版本号来源是正则定位 `<artifactId>case-flow-backend</artifactId>` **之后紧跟**的 `<version>`（去掉 `-SNAPSHOT`）——不能用第一个 `<version>`，那是 Boot parent 的 2.7.18。

**排除清单**：`node_modules` `dist` `target` `.venv` `.workbuddy` `__pycache__` `.git`、`.idea/shelf|httpRequests|dataSources|dictionaries|inspectionProfiles`、`*.pyc *.class *.log *.tmp *.trace.db`、一切 `.env*`（保留 `.env.example`）。

**不打 `tools/`**（体积 500M+，新电脑用已装好的 JDK8/Maven/Node）。打包后脚本会重开 zip 自校验是否混入排除项。

### 7.2 方言约定

`schema.sql` 保持 ANSI-ish 写法以兼容 H2：

- 不用 `ENGINE`、`ON UPDATE CURRENT_TIMESTAMP`
- `TEXT` 列**不带 DEFAULT**（MySQL 不允许），只写 NULL
- **`CREATE INDEX IF NOT EXISTS` 是 H2 语法，MySQL 8 不支持** → 二级索引全放 `index-mysql.sql`（15 条）

### 7.3 `SchemaMigration` 机制

`com.caseflow.bootstrap.SchemaMigration`，`@Component @Order(HIGHEST_PRECEDENCE)`，实现 `ApplicationRunner`。

**为什么需要它**：`schema.sql` 全是 `CREATE TABLE IF NOT EXISTS`，对**已存在**的表不补新列；而 MySQL 的 `ALTER TABLE ADD COLUMN` **不支持 `IF NOT EXISTS`**，没法把升级语句写进同一份脚本。于是把「缺哪列补哪列」的判断放到启动时做——两种方言通用，可重复执行。

**流程**：

1. `existingColumns(conn)` 用 `DatabaseMetaData.getColumns` 一次性拉全库 `表.列` 集合（全小写，规避 MySQL on Windows 大小写问题）
2. 遍历 `NEW_COLUMNS[][]` 数组，对缺失的逐条 `ALTER TABLE t ADD COLUMN c 定义`
3. 依次执行 6 个迁移/数据种子步骤：
   - `migrateCategory` —— 旧 `category` 存大类词 → 归位到 `case_type`，`category` 清空
   - `removeCivilType` —— `case_type='CIVIL'` 清回未分类
   - `seedCategories` —— `case_category` 为空时种入 14 条默认小类（刑事 5 + 行政 9）
   - `backfillFeedbackDeclare` —— 从存量 `content` 解析执行记录三要素拆列（幂等：只处理 `upload_platform IS NULL`）
   - `retireStdPlanTasks` —— `is_std=1` 的置 `CANCELLED`（不删行，保留办案留痕）
   - `migrateSingleDeadlineToTimeNodes` —— 把 `case_info` 单期限迁移为节点记录

**⚠️ 失败不阻断启动**：整个 `run()` 包在 try-catch 里，异常只 `log.error` 并打印所有待补列的 ALTER 语句，提示「撤回功能可能不可用」。

> **所以加迁移后必须用接口层再查一遍结果，别只信启动日志。**

### 7.4 新增列的完整步骤

**Step 1 — 改 `app/sql/schema.sql`**（唯一数据源）

- 不能含 `NOT NULL` 且无默认值（否则老数据行过不去）；例外：`TINYINT NOT NULL DEFAULT 0`
- `TEXT` 不带 `DEFAULT`
- 不用 MySQL 专有语法
- 二级索引用 `KEY` / `UNIQUE KEY` 写在建表里

**Step 2 — 在 `SchemaMigration.NEW_COLUMNS` 登记一行**

```java
{"表名", "列名", "列定义"},
```

格式固定 `{表名, 列名, 类型 NULL|TYPE NOT NULL DEFAULT X}`。**这步是必做的，漏了老库不会补列。**

**Step 3 —（如需）加索引到 `app/sql/index-mysql.sql`**

**Step 4 —（如需）改 Entity**（MyBatis-Plus 驼峰映射）

**Step 5 — 验证**

```bash
python scripts/check_schema_commas.py     # 静态体检：查漏逗号
python scripts/dev.py --no-frontend        # 看日志是否有 "[SchemaMigration] 已补列：xxx.yyy"
```

**Step 6 — 提交前 `git status --porcelain`**，确认没带 `caseflow.mv.db` 的运行变动。

### 7.5 ⚠️ 进快照的实体必须自定义 `insertWithId`

`IdType.AUTO` 会让 `updateById` / 插入时省掉主键列，导致**撤回还原时主键变了**（历史关联断裂）。

**凡是进 `CaseSnapshot` 的实体，Mapper 都要写 `insertWithId`（带显式主键插入）。**

> ⚠️ **写 `insertWithId` 时必须把该实体的所有列都写全。** 项目里已栽过：`CaseTodoMapper.insertWithId` 漏了 6 列（`opinion_id / parent_id / urgency / importance / dept_source / deadline`），撤回后待办丢失了意见关联和期限。**写完逐列对照实体核一遍。**

### 7.6 建案子表：必须 `addAllQuietly`

建案时嫌疑人、时间节点、待办走 `addAllQuietly` / `addDraftsQuietly`：**不单独打操作日志**。

否则建案会产生一串子表日志，占据「案件最新一步」，用户点撤回撤掉的是嫌疑人而不是建案本身。

- `excludePathPatterns`：`/auth/login` `/auth/register` `/auth/register/**` `/auth/roles` `/auth/logout` `/h2-console/**` `/console/**` `/error`
- OPTIONS 直接放行（CORS 预检）
- **`!(handler instanceof HandlerMethod)` 放行**（静态资源与欢迎页）—— 否则前端页面本身被当未登录返回 401 JSON，浏览器打开白屏
- token 读取：`X-Token` 头优先，`?token=` 兜底（SSE 用）

> ⚠️ `WebConfig:44-47` 有重要历史注释：早先写的是 `excludePathPatterns("/auth/**")` 把整个 `/auth` 放行，导致 `GET /auth/info` 里 `AuthContext` 永远是 null，**一直返回 401**。**以后往 `/auth` 加接口要想清楚是否登录前就要用。**

**`PermissionInterceptor`**：找方法上的 `@FullAccessOnly`，找不到再找类上的；有且 `!isFullAccess` → 403。

```java
@Target({ElementType.METHOD, ElementType.TYPE})
public @interface FullAccessOnly { String value() default ""; }   // value 用于 403 提示
```

> 类注释明确：**「权限边界集中在这里和 `Roles#isFullAccess`，不要散落到各处」。**

### 9.3 数据范围收敛

**唯一实现**：`CaseScopeService.myVisibleCaseIds()`

```
CurrentUser.employeeId != null
  → case_assignee 中该员工 status='ACTIVE' 的 case_id 集合
否则（未绑定员工的存量账号，如 boss/test1）
  → case_info 中 created_by = userId 的 id 集合
未登录 → Collections.emptySet()   ← 不返回 null
```

**对外唯一门面**：`CaseService.myVisibleCaseIds()`（内部委托）。

> **`CONTRIBUTING.md` 第五节第 6 条明文规定：新增「按人取案件」功能必须复用它。**
> `CaseScopeService` 是依赖链末端（只依赖两个 Mapper），为避免 `CaseService ↔ OpinionService` 循环依赖而抽离：
> ```
> CaseService ─┬─> OpinionService ──> CaseScopeService
>              └─> StaffTodoService ──┘
> ```

**收敛触发**：

```java
private boolean scopeToSelf(CaseQuery query) {
    if (!AuthContext.isFullAccess()) return true;             // 民警恒 true
    return Boolean.TRUE.equals(query.getOnlyMine());          // 管理层显式声明才收敛
}
```

即：**普通民警即使不传 `onlyMine` 也会被强制收敛**（`verify_scope.py` 验证这一点）。

### 9.4 为什么有些权限写在 Service 而不加注解

| 接口 | 原因（代码注释原文） |
|---|---|
| `TodoController.update` | 「改主任务仅管理层，改子任务承办人即可（子任务是干活的人自己拆的，写错了却改不了不合理）」 |
| `TodoController.remove` | 「那个注解由 PermissionInterceptor 在方法执行前拦截，会把民警挡在门外。但子任务恰恰是民警自己拆的，让他加得了一直删不掉不合理」 |
| `TodoController.updateFeedback` | 「民警改了上传文件名却提交不了」不合理 |
| `WatchController` 的流转/计划 | 「审批与强制措施为管理层专属（@FullAccessOnly），计划与经办人流转在 Service 内按承办关系校验」 |

### 9.5 账号与员工 1:1 绑定

- 唯一执行点：`service/EmployeeBindingService`。**一名员工只能绑一个账号**；`org_employee.origin` 记来源（`SELF_REGISTER` 等）
- **普通民警能操作自己案件的前提**：`employeeId == null` 时 `PlanService.checkOperate` / `ApprovalService.checkHandlerOrManager` 直接 403
- 存量 `boss` 仍 `employee_id = null`（**刻意不回填**）
- `PUT /users/{id}`：**传 `employeeId` 才改绑，留空维持原样**（不能解绑）

### 9.6 会话：`TokenStore`

- `ConcurrentHashMap<String, SessionInfo>`，token 是 UUID 去横线的 32 位字符串
- **同账号最多 5 个会话**（`MAX_SESSIONS_PER_USER`），超出挤掉最早的（刻意支持电脑+手机+平板同时在线）
- `removeAll(userId)`：停用/删除/重置密码时全部踢下线
- `cleanupExpired()` 每次操作时清理
- **进程内存态：后端一重启全员掉线**（前端表现为一屏 401 + 满屏 0；路由守卫会提前用 `/auth/info` 验一次并跳登录页）

## 第 10 章 前端架构与约定

### 10.1 路由与三道守卫（`router/index.js`）

```js
const STAFF_PAGES = ['/my-cases', '/reminders', '/my-todos', '/case-type']
```

**用白名单而不是逐页打标**——以后新增页面默认就是管理层专属，不会漏配。

> ⚠️ `/case-type` **必须**在白名单里：否则民警点受门控栏目 → 被弹到类型选择页 → 又被弹回 `/my-cases` → 形成循环，表现为**菜单点不动**。

守卫顺序（**顺序不能乱**）：

```
1. public？→ 放行
2. 无 token？→ /login
3. 令牌真伪校验（一次性，结果按令牌值缓存）
     ├ 401 → /login?expired=1
     └ 网络错误/后端未起 → 照常放行（否则后端启动稍慢就把人踢出去）
4. 非全权限且不在白名单 → /my-cases
5. meta.fullAccessOnly 且非全权限 → 落地页
6. meta.systemManageOnly 且非系统管理员 → 落地页
7. GATED_PATHS 且未选类型 → /case-type?from=<目标完整路径含 query>
```

### 10.2 案件类型门控（`store/caseType.js`）

```js
GATED_PATHS = ['/watch', '/todos', '/cases', '/reminders', '/case-boards']
```

**统一口径函数 `withCaseType(params)`**：所有受门控栏目的请求都必须走它，把当前类型混入查询参数。集中成一个函数，让「锁定类型」**默认生效**，漏一个就出现「列表锁了类型、图表没锁」的错位。

**两道拦截各司其职**：侧栏 `onSelect`（避免先闪一下再被弹回）+ 路由守卫（防手敲地址/刷新）。

`parseLevel3` 只接受 `LEVEL3_PATHS` 里的落点，非法值退回 `/cases`，防止 `from` 参数被构造成跳任意路由。

**生命周期**：切栏目不重置、刷新不重置、**点「退出」登录会清空**（否则下一个人会继承上一个人的类型）。

### 10.3 侧栏分档（`store/user.js`）

**唯一判据入口**：

```js
export const navTierOf = (role) => {
  if (!isFullAccessRole(role)) return NAV_TIER.STAFF
  return isSystemAdminRole(role) ? NAV_TIER.ADMIN : NAV_TIER.LEADER
}
```

`NavPanel.vue` 与路由守卫**共用**它。

> **菜单分档 ≠ 权限分档。** LEADER 与 ADMIN 的业务写权限完全相同，差别只在于能不能看到系统管理三栏目。

### 10.4 ⚠️ 加查询字段必须同时改三处

`CaseController.page()` / `WatchController.cases()` 都是**逐字段手工搬** `@RequestParam → CaseQuery`（**不是 `@ModelAttribute`**）。

**新增查询条件：DTO + 控制器 + buildWrapper 三处缺一不可**，漏控制器那一处会**静默丢掉条件**（页面点了没反应、接口不报错）。

**⚠️ 第三种形态**：`/cases/stats`（图表）**不经过 `buildWrapper`**，有自己的 `StatsService.stats(days, caseTypes, dueBuckets, priorities, restrict)` 签名，前端 `loadStats` 是另一条取数路径。**列表加了筛选 ≠ 图表跟着筛。**

改图表筛选时**先 grep `loadStats` 看它传了什么**，别假设「后端统一处理了」。

**前端口径**：新增 `reload() = load() + loadStats()`，所有筛选控件走 `reload`。**`reset()` 尤其容易漏**（它清筛选却不刷图表）。

只接聚合后仍有意义的维度（重点/到期桶/优先级）；**关键字/经办人/分类不接**（趋势图会退化成单点）。

### 10.5 列表返回体字段名

`/cases` 等分页接口返回 **`{list, total, page, size}`**，**不是 `records`**。模糊查字段名是 **`keyword`**，**不是 `name`**。写 e2e / 脚本时别猜。

### 10.6 组件类选择器要选专属类

`.cf-panel` 这类通用类会命中外层包装拿到空壳（项目因此给阶段条定 `.cf-stagebar`）。给新组件加样式钩子时用**带语义前缀的专属类**。

### 10.7 共享组件约定

| 组件 | 约定 |
|---|---|
| `TodoBatchEditor` | `c(sfx)` **必须双写 class**：同时给 `cf-bt__sfx` 与 `${scope}__sfx`（e2e 按 scope 定位）。`preset-mode`：`fill`（点标签填进第一空行）/ `submit`（直接落库） |
| `FocusStar` / `FocusOnlyToggle` | 四栏目**统一口径**。组件内部自己按 `isFullAccess` 收敛，不要各页再判一次 |
| `CaseTable` | `compact` / `full` 两模式；`show-case-no` 控制编号列 |
| `EChart` / `ChartPanel` | 视口固定高度，画布按数据量长高，超出用原生滚动条（**不要把条子压扁**） |
| `EmployeePicker` | 无行内勾选框。流程是「关键词检索 → 结果表 → 点该行『主办』/『协办』」 |

### 10.8 ⚠️ 交互行为约定（写新页面时必须遵守）

1. **禁止悬浮提示（tooltip）承载关键信息。** 项目统一改成**常驻可见文字**（「可以滑动」「查看案件 →」等）。悬浮在长列表里基本没人找得到。
2. **禁止用「按钮凭空消失」表达权限/状态。** 给明确提示（「由办案人本人点击开始侦查」「只有案件承办人或管理层可以勾选待办完成」）比让按钮消失更好——后者会让人以为系统坏了。
3. **「为什么做不了」的说明要内联可见**，不能用悬浮（会挡住旁边的操作按钮）。
4. **同类控件在不同页面落位可以不同**，但**同一页面的控件形态要一致**。别把一页的解法套到另一页上。
5. **列表、图表、看板、汇总卡片必须同口径刷新**。只改一个就出现用户看不懂的对不上。
6. **落地页消费 `?caseId=` 必须放 `onMounted`，不能放 `watch(route.query, {immediate:true})`**——immediate watcher 在 setup 期间同步执行，此时导航还没落地，里面再 `router.replace` 等于发起第二次导航把本次 push 顶掉（表现为「地址栏变了，详情抽屉却没开」）。
7. **定位锚点用完即抹**：`caseId/todoId/subtaskId` 处理完从地址栏清掉，否则刷新会重复弹抽屉。
8. **同一句话 3 秒内只弹一次**（工作台一次并发十几个请求，不去重就是一屏重复红条，看着像页面崩了其实只有一件事）。
9. **测「文字被裁」的正确判据**：`scrollWidth` 测不出来（overflow:hidden 时等于 clientWidth）；也不能按「控件宽 − padding − 图标」倒推（`el-select__selection` 里还塞着隐藏的 `.el-select__input-wrapper`）。**正解：可用宽 = 文字元素实际渲染宽度，需要宽 = canvas `measureText()` 像素宽**；测两遍（占位 + 最长预设值）。

### 10.9 ⚠️ `el-cascader` / `el-select` 在 e2e 里的坑

- cascader 面板 teleport 到 body 且 fixed 定位，**`offsetParent` 恒 null**，`element.click()` **不触发 hover 联动** → 只能用键盘：`click(.el-input__wrapper)` → `ArrowDown` … → `Enter` 循环
- **el-select 没焦点时点一次打不开**（`menuVisibleOnFocus` 吃掉首次点击）：点一次 → inspect → 没开再点
- **el-date-picker 根元素也带 `el-input` 类**：CSS（含 grid-area）按自定义类定位，用 `.el-input` 会命中错栅格

### 10.10 SSE

- 登录后建一条长连接 `/events/stream?token=`
- 工作台 2 秒防抖合并；案件详情 800~1000ms；待办面板 400ms
- **连续失败超 5 次停止重连**
- ⚠️ **服务端是全站广播，不按人过滤**（见 §14）

> ⚠️ H2 profile 时**必须 `cd` 到库所在目录**（§4.5）。

### 12.3 内网服务器（Nginx + 独立 jar，**推荐给正式使用**）

**结论：Nginx + 独立 jar，不是一个 jar 全包。**

服务器只装三样：**JDK 8/11、MySQL 8、Nginx**。Node/Maven/Python 不需要。

```
D:\caseflow\
├─ jdk\ mysql\ nginx\
├─ app\ case-flow-backend.jar  application-prod.yml  logs\
├─ www\                    ← frontend/dist，Nginx root
├─ data\ uploads\ mysql-data\
└─ backup\
```

后端启动（**三个必参**）：

```
java.exe -Xmx1536m -Dfile.encoding=UTF-8 -jar case-flow-backend.jar ^
  --spring.profiles.active=mysql ^
  --server.address=127.0.0.1 ^   ← 只监听本机，8080 不对内网开放
  --server.port=8080 ^
  --caseflow.upload-dir=D:\caseflow\data\uploads
```

Nginx 关键配置：

```nginx
location / {
    root D:/caseflow/www;
    try_files $uri $uri/ /index.html;
    gzip on;
}
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    client_max_body_size 100m;      # 必须 ≥ multipart max-request-size
    proxy_read_timeout 120s;        # 必须，SSE 需要长连接
}
```

服务化：Windows 用 WinSW（`onfailure action="restart" delay="10 sec"`），注册顺序 **MySQL → 后端 → Nginx**；Linux 用 systemd（`After=mysql.service`、`Restart=always`）。**Windows Update 必须设为手动**。

容量建议：4 核 8G、`-Xmx1536m`、`MYSQL_POOL_SIZE=20`、`innodb_buffer_pool_size` = 物理内存 50%。**明确反对引入负载均衡和集群**（10–50 人同时在线通常 <10）。

> **历史坑**（已修）：选「一个 jar 全包」时 `context-path=/api` 导致页面必须挂 `/api/` 下，且 `LoginInterceptor` 拦 `/**` 会把 `index.html` 与 `/assets/*.js` 当未登录返回 401 → 白屏。当前 `LoginInterceptor` 已加 `!(handler instanceof HandlerMethod)` 放行。

### 12.4 跨网访问

**先解决防火墙**：本机能开而手机开不了 = Windows 拦入站放行出站（实测本机 `WLAN → Public`，无放行规则）。

| 方案 | 范围 | 延迟 | 带宽 | 地址 | 安全 |
|---|---|---|---|---|---|
| ① 局域网直连 | 同一 WiFi | 2–10ms | 局域网 | 会变 | 最高 |
| ② **Tailscale / ZeroTier** | 任意网络 | 直连 20–60ms | 不限速 | **固定（MagicDNS）** | 高 |
| ③ cpolar 内网穿透 | 任意网络 | 100–300ms | **免费版 1Mbps** | 免费版 24h 换一次 | **最低（公网可达）** |
| ④ 单位 VPN | 单位网络内 | 依单位 | 依单位 | 通常固定 | 高 |

**建议顺序**：① 放行防火墙 → ② Tailscale（长期自用）→ ③ cpolar（仅临时演示）→ ④ 正式上线走单位 VPN。

cpolar 上线前**必做 8 项加固**：附件下载改一次性短票据、密码 ≥8 位 + 复杂度、登录失败 5 次锁 5 分钟、关 h2-console、CORS 白名单、附件下载记审计、HTTPS、访问控制密码。

## 第 13 章 排障手册

### 13.1 「接口返回 0 条 / 数据好像没了」

**先怀疑工作目录，再怀疑数据。**

```bash
ls data/h2/                              # 根目录有没有多出空库？
ls -l app/backend/data/h2/caseflow.mv.db # mtime 变过没？
```

- **根目录多出 `data/h2/caseflow.mv.db`** → 在错误的目录启动过后端。**真库安全**（mtime 没变），清掉多余文件，`cd app/backend` 重启即可
- **mtime 变了但数据仍不对** → 才去查数据

### 13.2 「mvn package 好像没生效 / jar 是旧的」

运行中的后端占着 jar，repackage 静默失败（`-q` 下几乎看不出）：

```bash
netstat -ano | findstr :8080     # 找 LISTENING 的 PID
taskkill /PID <pid> /F           # 只杀 LISTENING 的，宽匹配会杀掉 Vite 的连接
```

然后重新 package。

### 13.3 「文件上传总是失败 / 报 413」

按顺序检查：

1. `spring.servlet.multipart` 下是否配了？（写成 `server.servlet.multipart` **不生效**，退回 1MB）
2. Nginx 的 `client_max_body_size` 是否 ≥ `max-request-size`（100MB）？
3. 单文件是否超 `max-file-size`（50MB）？

### 13.4 「数据库连不上」

| 症状 | 原因 | 处理 |
|---|---|---|
| `Unsupported character encoding 'utf8mb4'` | MySQL 连接串 `characterEncoding` 写成了 utf8mb4 | 改成 `UTF-8` |
| `Schema "public" not found`（H2 Shell） | 连接串没带全参数 | 加 `MODE=MySQL;DATABASE_TO_LOWER=TRUE;CASE_INSENSITIVE_IDENTIFIERS=TRUE` |
| MySQL 启不来 / datadir 被截断 | 路径含中文 | MySQL 装到纯 ASCII 路径 |
| H2 `Database may be already in use` | 另一个进程占着（换端口没用，锁在文件上） | 停掉另一个后端 |
| `git checkout` mv.db 报 Permission denied | 后端在跑（正常现象） | 停后端 |

### 13.5 「后台全是 0 / 一屏 401」

**令牌是进程内存态，后端一重启全员掉线。**

前端路由守卫会提前用 `/auth/info` 验一次并跳登录页（提示「登录已过期，请重新登录」）。重新登录即可。

> 若**没有**跳登录页而是一屏 401，说明前端拿到的是废令牌但守卫判定为「网络错误照常放行」。清 `localStorage.cf_token` 手动登录。

### 13.6 「工作台图表和列表条数对不上」

大概率是前端漏了 `reload()`（只 `load()` 没 `loadStats()`），或者新增筛选条件时**漏改控制器**导致条件被静默丢掉。

排查：

```bash
grep -n "loadStats" app/frontend/src/views/CaseList.vue   # 看它传了什么
grep -n "@RequestParam" app/backend/.../CaseController.java  # 看控制器有没有接住
```

### 13.7 「pytest 全绿但界面不对」

大概率是**后端没重启**（改了 Java）。前端改 `src` 会热更新，后端不会。

### 13.8 「H2 库被锁 / 删不掉」

后端在跑。停掉它。

### 13.9 「npm run build 报 vite 找不到」

```bash
cd app/frontend && npm install --include=optional
```

**不要跑 `npm ci`**（会先清空目录，被 safe-delete 拦）。

### 13.10 「脚本跑不起来」

| 现象 | 原因 |
|---|---|
| `ModuleNotFoundError: requests` | venv 未建或未装依赖（`verify_p0_fields` / `verify_persistence` / `verify_undo` 依赖） |
| `verify_scope.py` assert 失败 | 需先跑 `verify_lan.py` 生成 `e2e_staff` |
| `verify_undo.py` / `verify_persistence.py` 导入报错 | **硬依赖 MySQL**，H2 dev 模式跑不了 |
| e2e `Cannot find module puppeteer-core` | 硬编码路径需改（§11.3） |

### 13.11 「git push 报 CONNECT tunnel failed, 502」

**沙箱代理间歇性故障，不是凭据问题。** 别动 remote/凭据，隔一会儿重试。直连 `github.com:443` 不通，必须走代理。

## 第 14 章 已知技术债与加固路线

### 14.1 鉴权与会话

| # | 问题 | 影响 |
|---|---|---|
| 1 | **`TokenStore` 是进程内存态** | ①后端重启全员掉线；②**多实例部署时 A 实例签发的令牌 B 实例不认识**（多台电脑各启一套指向同一库的场景会大面积登录失败） |
| 2 | **SSE 全站广播，不按人过滤** | 普通民警的浏览器也会收到全所事件，靠客户端过滤。**同时扩大了信息暴露面** |
| 3 | **令牌可通过 URL 参数传**（`?token=`） | token 进访问日志、浏览器历史、Referer。附件下载也用它 |
| 4 | **无登录失败次数限制 / 无防爆破** | 密码只有 ≥6 位校验 |
| 5 | **撤回权限过宽** | 任何登录用户都能撤回任何一条案件操作，只做了「该案件上最新一步」这一层保护，**没有按人/按角色限制，也没有乐观锁**（两人同时撤回会互相覆盖） |

### 14.2 权限

| # | 问题 | 影响 |
|---|---|---|
| 6 | **`/employees` 4 个读接口未加固** | `GET /tree` `/search` `/depts` `/{id}` `/template` 都没有 `@FullAccessOnly`。**任何登录用户（含民警）都能拉全量员工图谱（含手机号、邮箱）** |
| 7 | **`/files` 全部接口无 `@FullAccessOnly`** | `GET /{id}/download` 登录即可下任意附件，**不校验该用户是否有权看这个案件，也不记审计** |
| 8 | **CORS 全开** | `allowedOriginPatterns("*")` + `allowCredentials(true)`，等于允许任意网站带用户凭据调接口 |
| 9 | **`/users` 类级 `@FullAccessOnly`，但 BOSS 与 CHIEF/DEPUTY_CHIEF/LAW_OFFICER 同属 `isFullAccess`** | 前端用 `systemManageOnly` 区分（仅 BOSS 能看到菜单），**但后端未区分**——手敲地址的话所长也能调账号管理接口 |

### 14.3 数据与功能

| # | 问题 | 说明 |
|---|---|---|
| 10 | 改造之前的历史操作记录没有状态快照 | **不可撤回** |
| 11 | `case_question` 表已下线但保留 | Controller/Service/Entity 已删，建表语句与 3 个补列登记**仍保留**（为老库结构一致 + 历史数据留档） |
| 12 | `case_plan` 的 `is_std=1` 模板任务已作废 | 与案件待办两套并行清单冲突，统一由 `case_todo` 承担。存量行被 `SchemaMigration` 置 `CANCELLED` |
| 13 | `case_info` 三列期限不删 | `deadline_label/deadline/remind_days` 是约 **140 处引用**的取数来源，且 `ORDER BY deadline` 靠索引。改为「`case_time_node` 真源 + 三列是主节点派生视图」 |
