# 内网共享部署方案（物理隔离 · 10–50 人）

> 前提：单位内网**完全物理隔离**，服务器不能出外网；使用规模 10–50 人；服务器操作系统待定。
> 目标：让全单位办案人员在浏览器里打开一个内网地址就能用，且能平稳运行、可备份、可升级。

---

## 一、结论先行

**两个决定：**

1. **部署形态：Nginx + 独立 jar**（不是"一个 jar 全包"）
   - 用户访问 `http://caseflow.单位内网域名/` —— 不带端口号，对四五十岁的使用者最友好
   - 前端静态文件由 Nginx 直接吐，**根本不经过 Spring**，可以顺带避开下面这个必踩的坑
   - ⚠️ 如果选"一个 jar 全包"：后端 `context-path` 是 `/api`，静态页面只能挂在 `http://ip:8080/api/` 下（URL 难看）；更麻烦的是 `LoginInterceptor` 拦的是 `/**`，只放行了 `/auth`、`/h2-console`、`/console`、`/error`，**`index.html` 和 `/assets/*.js` 会被当成未登录请求返回 401，打开就是白屏**。用 Nginx 托管就不存在这个问题。

2. **服务器系统：优先向 IT 要一台 Windows Server 虚拟机**
   - 项目现有资产（免安装 MySQL 脚本、`dev.py`、`.venv`）全是 Windows 原生的，**零改造**
   - 免安装版 MySQL 在物理隔离环境下优势极大：解压即用、不注册服务、不要管理员权限、卸载 = 删目录，符合内网"可回退、不动系统"的要求
   - 10–50 人的规模，Windows Server 2016+ 完全够用
   - **什么情况下选 Linux**：单位有成熟的 Linux 运维（能自己定 systemd、做日志轮转）。此时 `scripts/mysql_local.py` 用不了（那是 Windows 免安装版），要走系统包或官方 tar.gz 装 MySQL，其余脚本也要按 Linux 路径调整。

## 二、物理隔离下的"三道摆渡"

隔离不是障碍，反而让事情变简单：**打包全部在你现在这台能上网的机器上完成，服务器只接收成品**。

### 2.1 服务器上「不需要」装的东西（重要）

| 组件 | 要不要装到服务器 | 说明 |
|---|---|---|
| Node.js / npm | ❌ 不需要 | 前端在打包机 build 好，服务器只放静态文件 |
| Maven | ❌ 不需要 | jar 在打包机已经打好，含全部依赖 |
| Python | ❌ 不需要 | 建库改用纯 SQL 脚本，不依赖 `.venv` |
| Java JDK/JRE | ✅ 要 | 与打包机同版本（建议 JDK 8 或 11） |
| MySQL 8 | ✅ 要 | 免安装 zip 版即可 |
| Nginx | ✅ 要 | 官方 zip（Windows）/ tar.gz（Linux） |

**这条很关键：隔离环境最容易把"把整个开发环境搬进内网"当成方案，结果引进一堆用不上的东西。服务器上真正需要的只有三样：JDK、MySQL、Nginx。**

### 2.2 打包机（能上网的开发机）产出清单

```
case-flow-backend.jar        后端可执行 jar（含所有依赖）
www/                         前端静态文件（原 frontend/dist）
sql/schema.sql               建表（H2/MySQL 通用）
sql/index-mysql.sql          MySQL 专用索引
data/员工图谱模板.xlsx        导入模板（生成命令见 README）
```

生成命令：

```bash
# 后端（在能上网的机器上执行，Maven 会把依赖都拉进 jar）
cd backend && mvn clean package -DskipTests
# 产出 backend/target/case-flow-backend.jar

# 前端
cd frontend && npm ci && npm run build
# 产出 frontend/dist/  ← 整个目录即 www/
```

> 已实测：本项目前端 `vite build` 通过，产物约 2.5MB（gzip 后约 1MB），12 秒完成。

### 2.3 需从介质引进服务器的软件

| 软件 | 获取方式 | 备注 |
|---|---|---|
| JDK 8/11 | 官网离线安装包 | 与打包机版本一致，避免 class 版本不兼容 |
| MySQL 8 zip | 官网免安装版 | 约 300–500MB |
| Nginx | 官方 Windows zip | 约 2MB，解压即可 |

用移动存储或单位的内网摆渡流程送进去，**每一步都记一笔（文件名 + 校验值 + 时间）**，内网作业留痕是基本要求。

## 三、内网服务器目录规划

统一的目录结构，升级和备份都会简单很多：

```
D:\caseflow\                     （Linux: /opt/caseflow/）
├─ jdk\                          解压的 JDK
├─ mysql\                        MySQL 免安装版
├─ nginx\                        Nginx
├─ app\
│  ├─ case-flow-backend.jar      后端
│  ├─ application-prod.yml       外部配置（见下）
│  └─ logs\                      应用日志
├─ www\                          前端静态文件（Nginx 的 root）
├─ data\
│  ├─ uploads\                   案件附件（务必独立、务必备份）
│  └─ mysql-data\                MySQL 数据文件
└─ backup\                       备份输出
```

**附件目录必须用绝对路径。** 现在配置里是 `./data/uploads`（相对启动目录），一旦有人从别的目录启动，附件就全"不见了"。部署时用启动参数覆盖：

```
--caseflow.upload-dir=D:\caseflow\data\uploads
```

## 四、逐步实施

### 第 1 步：服务器基础环境

```bash
# 检查 Java
D:\caseflow\jdk\bin\java -version

# 初始化 MySQL（免安装版，只需一次）
D:\caseflow\mysql\bin\mysqld --initialize-insecure --datadir=D:\caseflow\data\mysql-data
# 启动
D:\caseflow\mysql\bin\mysqld --defaults-file=D:\caseflow\mysql\my.ini
```

> ⚠️ **MySQL 的数据目录不要放在含中文的路径下。** 这个项目踩过：`mysqld` 会把参数里的路径在第一个非 ASCII 字符处截断，报 `Failed to set datadir`。所以 `D:\caseflow\` 这种纯 ASCII 路径最省事。

### 第 2 步：建库（纯 SQL，服务器上不需要 Python）

隔离环境下服务器没有 Python，把下面这段存成 `init.sql`，用 MySQL 客户端执行即可（等价于项目里的 `scripts/init_db.py`）：

```sql
CREATE DATABASE IF NOT EXISTS `case_flow`
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- 应用专用账号：只给 case_flow 库的权限，不给全局权限
CREATE USER IF NOT EXISTS 'caseflow'@'127.0.0.1' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON `case_flow`.* TO 'caseflow'@'127.0.0.1';
FLUSH PRIVILEGES;
```

然后：

```bash
mysql -u root -p < init.sql                    # 建库 + 建账号
mysql -u root -p case_flow < sql/schema.sql    # 建表
mysql -u root -p case_flow < sql/index-mysql.sql  # 建索引
```

最后插入首个管理员账号（**建议插入前先把密码改成 BCrypt 值**，见第七节）：

```sql
INSERT INTO sys_user (username, password, display_name, role, status)
VALUES ('boss', '待替换为BCrypt值', '张三（大队长）', 'BOSS', 1);

-- 员工账号：sys_user.employee_id 字段已预留与员工图谱的关联，务必填上
INSERT INTO sys_user (username, password, display_name, role, employee_id, status)
VALUES ('zhangsan', '待替换为BCrypt值', '张三', 'STAFF', 12, 1);
```

### 第 3 步：启动后端

```bash
cd D:\caseflow\app
D:\caseflow\jdk\bin\java.exe -Xmx1536m -Dfile.encoding=UTF-8 ^
  -jar case-flow-backend.jar ^
  --spring.profiles.active=mysql ^
  --server.address=127.0.0.1 ^
  --server.port=8080 ^
  --caseflow.upload-dir=D:\caseflow\data\uploads
```

三个必须注意的参数：

- `-Dfile.encoding=UTF-8` —— Windows 上不加，中文日志和中文文件名可能乱码。
- `--server.address=127.0.0.1` —— 后端**只监听本机**，外部一律走 Nginx。这样 8080 不需要对内网开放，攻击面小一半（数据库 3306 同理，只监听本机）。
- `--caseflow.upload-dir=绝对路径` —— 见上。

### 第 4 步：配置 Nginx

```nginx
server {
    listen       80;
    server_name  caseflow.xx.local;   # 或直接写内网 IP

    root   D:/caseflow/www;
    index  index.html;

    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1k;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;

        # ⚠️ 必须加，且要 ≥ 后端的 max-request-size(100MB)
        # Nginx 默认只有 1MB，不加这个，上传案件材料必然报 413
        client_max_body_size 100m;

        proxy_read_timeout 120s;
    }
}
```

> 前端是 **hash 路由**（地址栏形如 `#/cases`），所以严格来说连 `try_files` 都不需要——这是选用 hash 路由白送的好处，永远不会出现"刷新页面 404"。

### 第 5 步：做成服务（开机自启 + 崩溃自动拉起）

**Windows**：用 WinSW（单个 exe + 一个 xml）。关键内容：

```xml
<service>
  <id>CaseFlow</id>
  <name>案件指派系统</name>
  <executable>D:\caseflow\jdk\bin\java.exe</executable>
  <arguments>-Xmx1536m -Dfile.encoding=UTF-8 -jar D:\caseflow\app\case-flow-backend.jar --spring.profiles.active=mysql --server.address=127.0.0.1 --caseflow.upload-dir=D:\caseflow\data\uploads</arguments>
  <workingdirectory>D:\caseflow\app</workingdirectory>
  <env name="MYSQL_HOST" value="127.0.0.1"/>
  <env name="MYSQL_USER" value="caseflow"/>
  <onfailure action="restart" delay="10 sec"/>
  <logmode>roll</logmode>
</service>
```

MySQL 和 Nginx 同样注册成服务，**顺序：MySQL → 后端 → Nginx**。Nginx 挂成服务时注意设为"自动（延迟启动）"，避免开机时抢在 MySQL 前面。

**Linux**：标准的 systemd unit（`After=mysql.service`，`Restart=always`，`RestartSec=10`），Nginx 用系统包自带的服务。

> Windows 上务必把 **Windows Update 设成手动**。内网服务器半夜自动重启打补丁，第二天全单位打不开系统，这个锅不好背。

### 第 6 步：访问地址

- 首选：让 IT 在内网 DNS 上给个域名，比如 `caseflow.xx.local`。**四五十岁的使用者记不住 `10.20.30.41:8080` 这种地址**，给个能记住的名字，写在使用手册和桌面上。
- 兜底：`http://10.20.30.41/`（Nginx 占了 80，所以不用带端口）。
- 需要放行的：**只放 80**。8080、3306 保持只监听本机。

## 五、容量参数（10–50 人）

不用过度设计，这个规模的默认值基本够用，需要调的就这几处：

| 项 | 建议值 | 说明 |
|---|---|---|
| 服务器配置 | 4 核 8G / 系统盘 100G + 数据盘 500G | 磁盘按附件量估，见下 |
| JVM 堆 | `-Xmx1536m` | 50 人日内并发很低，1.5G 够；机器只有 4G 内存就设 1G |
| MySQL 连接池 | `MYSQL_POOL_SIZE=20` | 后端默认 10 也够，20 更稳 |
| `innodb_buffer_pool_size` | 物理内存的 50%（8G 机器设 4G） | 提升最大的一个 MySQL 参数 |
| 附件磁盘 | 按「案件数 × 平均附件大小 × 2」估 | 若 5000 案 × 2 附件 × 3MB ≈ 30GB，留 10 倍余量 |

**并发真相**：50 个人的单位，实际同时在线通常不超过 10 人，峰值就是上班后那半小时。单实例绰绰有余，**不要引入负载均衡和集群**——那是给自己找运维负担。

## 六、部署之前必须先补的两件事

这两件比部署本身更关键，不补的话系统上线当天就会出现问题。

### 6.1 账号体系目前是空的

现状核实：后端只有 `login / logout / info / dict` 四个接口，**没有任何注册或用户管理功能**，系统里只有一个演示账号 `boss / admin123`。

如果 50 个人共用这一个账号：

- 操作日志里的"操作人"全是同一个人 → **你想做的追溯和撤回功能直接失效**（撤回的前提是"谁改的"可信）
- 没法停用离职人员
- 出问题无法定位到人

需要补的最小集合：

1. 账号管理页（新建 / 停用 / 重置密码），仅 BOSS 可用
2. **账号与员工图谱绑定** —— `sys_user.employee_id` 字段已经预留了，填上之后员工登录就能直接看自己的案件，这是现成的设计
3. 首次登录强制改密码
4. 密码改 BCrypt 哈希存储（现在是明文）

### 6.2 四处演示级配置要收紧

内网 ≠ 安全，同一内网里的任何一台机器都能访问，而且这类系统通常要过等保测评。

| 项 | 现状 | 处理 |
|---|---|---|
| 密码存储 | 明文 `VARCHAR(128)` | 换 BCrypt 哈希（原列长度够用） |
| Token 传递 | 支持 `?token=xxx` URL 参数（`LoginInterceptor` 里） | **去掉**这个分支——token 会进访问日志和浏览器历史 |
| CORS | `allowedOriginPatterns("*")` + `allowCredentials(true)` | 同源部署后不需要跨域，直接去掉或限定内网域名 |
| 接口文档/控制台 | dev profile 下 h2-console 开启 | 生产 `SPRING_PROFILES_ACTIVE=mysql`，该开关自然关闭 |

顺带：`LoginInterceptor` 现在拦 `/**` 却没放行静态资源，如果哪天改成"一个 jar 全包"的部署方式，必须补上放行，否则页面白屏（这是最容易在部署当天卡住人的一个点）。

## 七、备份与升级

### 7.1 备份（必须有，且要验证过能恢复）

三样东西要备份，缺一不可：

```bash
# 1. 数据库（每天 02:00，保留 30 天）
mysqldump -u caseflow -p'密码' --single-transaction --routines case_flow | gzip > D:\caseflow\backup\db_%DATE%.sql.gz

# 2. 附件目录（案件原始材料，丢了无法重建）
#    用 robocopy 增量同步到备份盘
robocopy D:\caseflow\data\uploads E:\backup\uploads /MIR /R:1 /W:1

# 3. 配置与 jar（升级出问题时要能退回去）
copy D:\caseflow\app\*.* E:\backup\app\
```

**关键动作**：备份脚本上线后，**至少手工演练恢复一次**（在测试库上还原一份）。没验证过的备份等于没有备份。

### 7.2 升级流程

```
1. 停服务（后端 → 应用）          ← 先备份数据库和附件
2. 备份：db + uploads + 旧 jar
3. 替换 jar / 换 www 目录
4. 启服务，看日志有没有异常
5. 用演示账号走一遍核心链路（登录 → 建案 → 指派 → 办结）
6. 有问题就回退：换回旧 jar + 还原数据库
```

**回退准备要在升级前做完**，不要等出问题才想。数据库加字段这种改动（本项目走 `SchemaMigration` 自动补列）通常是向前兼容的，但改结构前一定先备份。

## 八、上线验收清单

部署完，按这个清单逐项过一遍：

- [ ] 内网任意一台电脑用浏览器能打开 `http://caseflow.xx.local/`
- [ ] 用**新建的普通员工账号**登录（不是 boss）能正常进入
- [ ] 4 个功能页都打得开，图表正常显示
- [ ] 建一个案件 → 指派 → 改期限 → 办结，全链路走通
- [ ] **上传一个 10MB 以上的 PDF 附件**（验证 Nginx `client_max_body_size`）
- [ ] **导入员工图谱 Excel**（验证中文文件名和并发上传）
- [ ] 打开"最近操作"，点开一条记录能看到变更明细与撤回按钮
- [ ] 断开服务器网络/重启服务器，服务能自动起来（验证服务化配置）
- [ ] 附件目录、日志目录有写权限，重启后文件还在
- [ ] 数据库备份脚本能跑通，**并演练过一次恢复**
- [ ] 服务器时间与内网时间服务器同步（时间不对会导致"逾期"判断全错，这条极易被忽略）
- [ ] Windows Update 设为手动 / 确认不会被自动重启
- [ ] 8080、3306 从内网其他机器**访问不通**（验证只监听本机）
- [ ] 写一页纸质/单页操作说明发给使用者（登录地址 + 账号 + 三个最常用动作）

## 九、一句话总结

> 在能上网的机器上把 jar 和前端静态文件打好，只把 JDK、MySQL、Nginx 三样软件和一堆成品摆渡进内网；服务器上 Nginx 占 80 端口对外，后端和数据库都只监听本机；然后**先补账号体系和密码加密，再开门给全单位用**。
